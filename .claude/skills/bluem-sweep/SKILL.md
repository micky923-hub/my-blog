# 프로젝트 청소 순서

1. **찾기**: 기본 브랜치를 최신으로 받고 `node harness/checks/sweep.mjs --fetch --save` → `_workspace/sweep/YYYY-MM-DD.md`.
2. **판단**: 목록은 후보다. 항목마다 "청소 PR에 넣음 / 대표 승인 필요 / 그대로 둠"으로 나눈다.
   * 사진은 코드가 이름을 조합해 부르는지 먼저 찾아본다.
   * 숨김 처리한 내용, 고객 자료 자리, 다른 저장소 이야기는 그대로 둔다.
3. **청소 PR**: 브랜치에서 확실히 안전한 것만 고친다 (문서의 틀린 경로, 확인된 안 쓰는 파일, 끝난 TODO). 관문 통과 후 PR. 머지는 대표 "머지해줘" 뒤.
4. **승인 필요한 것**: 원격 브랜치 지우기처럼 되돌리기 어려운 일은 목록만 대표에게 보인다.
5. **보고**: 찾은 것 → 청소 PR → 승인 필요한 것 → 그대로 둔 것과 이유, 5줄 이내.
6. **같은 것이 반복되면**: `harness/core-rules.md`의 "하네스 피드백"으로 알린다.
* 그 프로젝트만의 예외(늘 건너뛸 경로)는 `harness.config.json`의 `"sweep": { "ignore": ["경로 앞부분"] }`에 적는다. 지난 작업 기록(파일 이름에 spec·review·instructions·changelog 낱말이 든 문서, 예: `video-review.md`)은 그때의 경로라 "없는 파일"을 찾지 않는다. 낱말을 바꾸려면 `"records": [...]`에 적는다.
