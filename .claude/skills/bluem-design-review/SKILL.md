# 디자인 점검 순서

1. **기준 읽기**: 프로젝트 `CLAUDE.md`의 "브랜드"(색·글꼴·말투·디자인 톤) → `harness/type-rules.md`의 "디자인 기준".
2. **기계 검사**: `bash harness/checks/gate.sh`(디자인 검사 포함) → `node harness/checks/screenshots.mjs`. 빨간불은 먼저 고친다. 화면 검사의 `[참고]` 작은 글씨 목록도 본다.
3. **휴대폰부터 보기**: `_workspace/screenshots/`의 `*-mobile.png`를 먼저 연다. 아래 6가지를 차례로 본다.
   * 첫 화면: 무슨 회사인지, 다음에 누를 곳이 바로 보이나
   * 글씨: 읽기 편한 크기·줄 간격인가, 너무 긴 줄은 없나
   * 색: 브랜드 색과 맞나, 글자가 배경에 묻히지 않나 (밤 모드가 있으면 같이)
   * 누르는 곳: 버튼이 손가락으로 누르기 충분히 큰가
   * 사진: 흐리거나 늘어나지 않았나, 남의 이미지는 없나
   * 일관성: 버튼·카드·제목 모양이 페이지·언어마다 같은가
4. **PC 보기**: `*-desktop.png`에서 너무 넓게 퍼지거나 빈 곳이 어색한 곳을 본다.
5. **고치기**: "꼭 고칠 것"(읽기 어렵다, 깨졌다, 브랜드와 다르다)은 바로 고친다. 취향 문제("고치면 좋은 것")는 고치지 않고 제안만 한다.
6. **보고**: 대표에게 짧게 알린다. 꼭 고친 것 → 고치면 좋은 것(제안 1~3개) → 확인할 스크린샷 2~3장 파일 이름. 고객에게 물어야 할 것은 "(확인 필요)"로.
7. **커밋**: `bluem-commit-and-deploy` 순서를 따른다.
