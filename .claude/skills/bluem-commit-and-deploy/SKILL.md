# 커밋·배포 순서

1. **브랜치 확인**: `main`이면 새 브랜치를 만든다.
2. **관문 검사**: `bash harness/checks/gate.sh` (빌드·기본 검사·유형별 검사를 한 번에). 막히면 고친 뒤 다시 돌린다.
3. **배포 워크플로 확인**: 자동 배포가 있는 프로젝트면 배포 단계 앞에 `gate.sh`가 들어 있는지 본다. 없으면 대표에게 알린다.
4. **커밋**: `영역: 무엇을 바꿨나` 형식, 한국어로 짧게.
5. **푸시·PR**: PR 설명에 바뀐 것, 확인 방법, 스크린샷 위치를 적는다.
6. **관문 확인**: GitHub Actions가 모두 초록불인지 본다. 빨간불이면 로그를 읽고 고친다. 검사를 끄거나 건너뛰지 않는다.
7. **배포**: 대표가 "머지해줘"라고 하면 머지한다. 실제 배포 방법은 프로젝트 `CLAUDE.md`의 "배포" 항목을 따른다 (예: PC에서 직접 업로드).
8. **기록**: 회사 차원의 변화(오픈, 도메인 연결 등)는 대표에게 알려 본부의 프로젝트 목록을 고치게 한다.
