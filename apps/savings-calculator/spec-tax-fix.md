# 적금 계산기 세율 수정 계획 (spec-tax-fix)

> 작성: Plan 서브에이전트, 2026-10-09 · 지침: `.claude/tasks/savings-tax-fix/plan-instructions.md`
> 상태: **사용자 승인 대기**

## 0. 왜 고치나

"세금우대 9.5% (조합 예탁금 등)"는 지금 세법과 맞지 않는다.

- 9.5%는 **폐지된 세금우대종합저축**의 세율이다.
- 농협·신협·새마을금고 등 **조합 예탁금**(1인 3,000만 원 한도)은 이자소득세가 비과세이고 **농어촌특별세 1.4%만** 낸다.
- 2025.12 개정(국회예산정책처 「2025년 개정세법 심의 결과 및 주요 내용」, 하나은행 「2026년 시니어 절세 가이드북 ①」): 총급여 7,000만 원(종합소득금액 6,000만 원) **초과** 준조합원·회원은 2026년에 생긴 이자에 **5%**, 2027년부터 **9%** 분리과세. 농어민과 총급여 7,000만 원 이하는 1.4%가 그대로이고 비과세 기한이 연장됨.
- 위 내용은 메인 세션의 웹 검색 결과다. Plan 단계에서 원문을 직접 열어 보지는 않았다. 그래서 아래 두 가지는 **미확인**이다.
  - 연장된 비과세 기한의 정확한 연도
  - 5%·9%에 농특세가 따로 붙는지 여부

## 1. 옵션 설계

**바꿀 내용**: "세금우대 9.5%"를 **"조합 예탁금 1.4%"**로 바꾼다.

- taxCode: `95` → `14`
- 세율: `14/1000`
- 계산식(`Math.round(interest * taxCode / 1000)`)은 그대로 쓴다.

**고소득 준조합원 5%·9%는 어떻게 할까**

| 안 | 장점 | 단점 |
|---|---|---|
| A. 라디오 옵션으로 추가 (5%, 9%) | 고소득자가 정확한 숫자를 볼 수 있다 | 세금 선택지가 3개에서 5개로 늘어 모바일 한 줄에 다 들어가지 않는다. "2026년 발생분"처럼 연도 조건까지 설명해야 한다. 농특세가 따로 붙는지 몰라서(미확인) 숫자가 틀릴 수 있다 |
| **B. 안내 문구 한 줄로만 (권장)** | 선택지 3개를 그대로 둔다. 화면과 코드 변경이 가장 적다. 미확인 부분을 숫자로 단정하지 않는다 | 고소득 준조합원은 세후 금액을 직접 볼 수 없다 |

**권장: B안.** 단순함이 우선이다. 해당자는 일부이고, 세율 구조가 아직 바뀌는 중이다(2026년 5%, 2027년 9%). 나중에 원문을 확인하면 A안으로 넓힐 수 있다.

### `apps/savings-calculator/app.js`
- 21줄 주석: `154(일반) / 95(세금우대) / 0(비과세)` → `154(일반) / 14(조합 예탁금 농특세) / 0(비과세)`
- 51줄 검증: `taxCode !== 95` → `taxCode !== 14`
- 75줄 계산식은 바꾸지 않는다.

### `apps/savings-calculator/spec.md` (기록 문서 갱신)
- 24줄 표, 73줄 세율코드, 122줄 문구를 새 옵션에 맞게 바꾼다.
- 검증 예시 B는 새 세율로 다시 계산한 값으로 바꾼다. 같은 조건(예금 1,000만 원, 12개월, 연 3.5%, 월복리)에서 세율만 1.4%로 바꾼 값이다.

| # | 조건 | 원금 | 세전 이자 | 이자 과세액 | 세후 수령액 |
|---|---|---|---|---|---|
| B | 예금 1,000만 원, 12개월, 연 3.5%, 월복리, 조합 예탁금 1.4% | 10,000,000 | **355,670** | **4,979** | **10,350,691** |

손 계산:

- 세전 이자: (1 + 0.035/12)^12 = 1.0355669529… → 355,669.53 → 반올림 **355,670** (기존과 같음)
- 이자 과세액: 355,670 × 14/1000 = 4,979.38 → 반올림 **4,979**
- 세후 수령액: 10,000,000 + 355,670 − 4,979 = **10,350,691**

참고값(B안이라 화면에는 넣지 않음):

- 같은 이자에 5%를 적용하면 17,783.5 → 17,784원
- 같은 이자에 9%를 적용하면 32,010.3 → 32,010원

이 숫자는 Node로 확인했다. 지금 `calculate()`에 taxCode 95를 넣으면 33,789 / 10,321,881이 나온다. 이 값은 기존 spec과 일치한다.

## 3. 새 안내 문구 초안 (용어 풀이 155줄 교체)

```html
<li><strong>조합 예탁금 1.4%</strong>: 농협·수협·신협·새마을금고 등에 맡긴 돈은 1인 3,000만 원까지 이자소득세가 없고 농어촌특별세 1.4%만 내요. 조합원이나 준조합원(출자금을 내고 가입)이어야 해요. 3,000만 원을 넘는 부분은 일반 15.4%예요.</li>
<li class="sc-guide-note">총급여 7,000만 원을 넘는 준조합원은 2026년에 생긴 이자에 5%, 2027년부터 9%가 붙어요. 이 계산기에는 넣지 않았어요.</li>
```

- 두 번째 줄은 기존 `<li>` 스타일을 그대로 써도 된다. 새 클래스가 필요하면 `style.css`에 `sc-` 접두사로 추가한다.
- "3,000만 원을 넘는 부분은 일반 15.4%"는 웹 검색 요약을 근거로 했고 원문은 **미확인**이다. Build 전에 사용자가 맞다고 확인하면 그대로 쓰고, 아니면 이 문장을 뺀다.

## 4. 저장값 처리

- 확인 결과, `app.js`는 세금 선택을 localStorage, URL 해시, 쿼리 어디에도 저장하지 않는다. localStorage에는 `theme` 하나만 쓴다.
- 그래서 **옛 값 95를 따로 처리할 필요가 없다.** 새로고침하면 기본값 154로 돌아간다.
- 방어 코드도 추가하지 않는다. 혹시 95가 들어오면 지금처럼 "세금 종류를 골라 주세요." 오류를 띄운다.

## 6. 사용자 결정 사항

1. **5%·9% 처리**: 권장은 B안(안내 한 줄). A안(옵션 추가)을 원하는지.
