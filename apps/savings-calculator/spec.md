# 적금·예금 이자 계산기 — 계획서 (spec)

> 상태: **승인됨 (2026-10-08)** · 작성일 2026-10-08
> 위치: `apps/savings-calculator/` · 블로그: financialdiary.co.kr

---

## 1. 앱 개요

- **누가**: 블로그의 예금·적금·파킹통장·청년도약계좌 글을 읽는 재테크 입문자.
- **언제**: 은행 상품 금리를 보고 "그래서 만기에 실제로 얼마 받지?"가 궁금할 때.
- **왜**: 광고 금리와 실제 수령액(세금 15.4% 차감 후)의 차이를 바로 확인하고, 예금과 적금, 단리와 월복리, 일반과세와 비과세를 쉽게 비교하기 위해.

---

## 2. 기능 목록

### MVP (이번에 만들 것)

| 구분 | 내용 |
|---|---|
| 탭 | **예금**(목돈 한 번에 맡김) / **적금**(매월 같은 금액 납입) 전환. 탭을 바꿔도 입력값은 유지, 금액 라벨만 "예치 금액" ↔ "월 납입액"으로 바뀜 |
| 입력 | 금액(원), 기간(개월, 1~120), 연 이자율(%, 0~20, 소수 둘째 자리까지), 이자 방식(단리 / 월복리) |
| 과세 방식 | 일반과세 15.4% (기본값) / 비과세 0% / 조합 예탁금 1.4% (2026-10-09 세금우대 9.5%에서 수정) |
| 결과 | 원금 합계, 세전 이자, 이자 과세액, **세후 수령액**(가장 크게 강조) |
| 계산 시점 | 입력할 때마다 자동 계산 (`input` 이벤트). "계산하기" 버튼 없음 |
| 숫자 표시 | 금액 입력칸은 입력 중 천 단위 쉼표 자동 표시(`10,000,000`). 입력칸 아래에 한글 금액 보조 표시(예: "1,000만 원") |
| 빠른 입력 | 금액 칸 아래 `+10만` `+100만` `+1000만` 버튼, 기간 칩 `6개월` `12개월` `24개월` `36개월` |
| 잘못된 입력 | 빈칸·0·범위 초과 시 결과 대신 안내 문구 표시 (예: "기간은 1~120개월 사이로 입력해 주세요") |
| 안내 | 사용법 안내 문구 + 면책 문구 (4·5장) |
| 테마 | 블로그 라이트/다크 모드를 그대로 따름 |

### 나중에 할 것 (MVP 제외)

- 월별 이자 누적 표·그래프
- 두 상품 나란히 비교 모드
- 우대금리(기본+우대) 분리 입력, 중도해지 이율 계산
- 정부기여금(청년도약계좌) 반영
- 결과 링크 공유(URL 파라미터), 일 단위 기간 입력
- 연복리, 일복리 (파킹통장용)

## 3. 계산 공식

### 기호

| 기호 | 뜻 |
|---|---|
| `P` | 예금 예치 금액 (원) |
| `M` | 적금 월 납입액 (원) |
| `n` | 기간 (개월) |
| `r` | 연 이자율 ÷ 100 (예: 3.5% → 0.035) |
| `i` | 월 이자율 = `r / 12` |

### 네 가지 경우

| 경우 | 원금 합계 | 세전 이자 (반올림 전) |
|---|---|---|
| 예금 · 단리 | `P` | `P × r × n / 12` |
| 예금 · 월복리 | `P` | `P × ((1 + i)^n − 1)` |
| 적금 · 단리 | `M × n` | `M × i × n(n+1)/2` |
| 적금 · 월복리 | `M × n` | `M × [ (1 + i) × ((1 + i)^n − 1) / i − n ]` |

- **적금 단리 설명**: 첫 달에 넣은 돈은 n개월, 둘째 달 돈은 n−1개월, …, 마지막 달 돈은 1개월 동안 이자가 붙는다. 그래서 1+2+…+n = n(n+1)/2 개월치 이자.
- **적금 월복리 설명**: k개월 맡긴 납입분의 이자는 `M × ((1+i)^k − 1)`. 이것을 k = 1…n까지 더한 값이 위 식이다.
- **이자율 0%**일 때 월복리 식은 `i`로 나누므로 **0 나누기**가 생긴다 → `r = 0`이면 세전 이자를 바로 0으로 처리한다.

### 반올림·세금 규칙 (구현 시 반드시 이 순서)

1. **세전 이자** = 위 식 결과를 `Math.round()` → **원 단위 반올림**
2. **이자 과세액** = `Math.round(세전 이자 × 세율코드 / 1000)` → 원 단위 반올림
   - 세율코드: 일반과세 `154`, 조합 예탁금 `14`, 비과세 `0`
   - 소수(`0.154`)를 곱하지 않고 정수 코드로 계산해 부동소수점 오차를 피한다.
3. **세후 이자** = 세전 이자 − 이자 과세액
4. **세후 수령액** = 원금 합계 + 세후 이자
5. 화면 표시는 `toLocaleString('ko-KR')` + "원"

> 참고: 실제 은행은 소득세(14%)와 지방소득세(1.4%)를 따로 계산하고 10원 미만을 버리는 경우가 많아 몇십 원 차이가 날 수 있다. 이 차이는 면책 문구로 안내한다.

### 검산 예시 (Review 단계에서 이 값과 정확히 일치해야 함)

모두 `node`로 직접 계산해 확인한 값이다.

| # | 조건 | 원금 합계 | 세전 이자 | 이자 과세액 | 세후 수령액 |
|---|---|---|---|---|---|
| A | 예금 1,000만 원, 12개월, 연 3.5%, **단리**, 일반과세 | 10,000,000 | **350,000** | 53,900 | **10,296,100** |
| B | 예금 1,000만 원, 12개월, 연 3.5%, **월복리**, 조합 예탁금 1.4% | 10,000,000 | **355,670** | 4,979 | **10,350,691** |
| C | 적금 월 10만 원, 12개월, 연 3.5%, **단리**, 일반과세 | 1,200,000 | **22,750** | 3,504 | **1,219,246** |
| D | 적금 월 10만 원, 12개월, 연 3.5%, **월복리**, 비과세 | 1,200,000 | **22,995** | 0 | **1,222,995** |

손 계산 과정:

- **A**: 10,000,000 × 0.035 × 12/12 = 350,000. 세금 350,000 × 154/1000 = 53,900. 수령액 10,000,000 + 350,000 − 53,900 = 10,296,100.
- **B**: (1 + 0.035/12)^12 = 1.0355669529… → 이자 355,669.53 → 반올림 355,670. 세금 355,670 × 14/1000 = 4,979.38 → 4,979. 수령액 10,350,691.
  (같은 조건 일반과세라면 세금 54,773원)
- **C**: 100,000 × (0.035/12) × (12×13/2 = 78) = 22,750. 세금 22,750 × 154/1000 = 3,503.5 → 반올림 3,504. 수령액 1,200,000 + 22,750 − 3,504 = 1,219,246.
- **D**: 100,000 × [(1.0029167) × (1.0355670 − 1)/0.0029167 − 12] = 22,995.08 → 22,995. 비과세라 세금 0. 수령액 1,222,995.
  (같은 조건 일반과세라면 세금 3,541원)

추가 경계 확인용:

| 조건 | 기대 결과 |
|---|---|
| 이자율 0%, 아무 방식 | 세전 이자 0, 수령액 = 원금 |
| 기간 1개월, 적금 10만 원, 3.5% 단리 | 세전 이자 292원 (100,000 × 0.035/12 = 291.67 → 292) |

## 4. 사용법 안내 문구 (화면에 그대로 넣을 초안)

> **이렇게 사용하세요**
> 1. 위에서 **예금**(목돈을 한 번에 맡김) 또는 **적금**(매달 같은 금액을 넣음)을 고르세요.
> 2. 금액, 기간(개월), 은행에서 안내한 **연 이자율**을 입력하세요.
> 3. 이자 방식(단리/월복리)과 세금 종류를 고르면 결과가 바로 바뀝니다.
> 4. 맨 아래 **세후 수령액**이 만기에 실제로 통장에 들어오는 금액입니다.
>
> **용어 풀이**
> - **단리**: 원금에만 이자가 붙어요. 대부분의 은행 예·적금이 단리입니다.
> - **월복리**: 매달 붙은 이자에도 다시 이자가 붙어요.
> - **일반과세 15.4%**: 이자소득세 14% + 지방소득세 1.4%. 보통 이 경우입니다.
> - **조합 예탁금 1.4%**: 농협·수협·신협·새마을금고 등에 맡긴 돈은 1인 3,000만 원까지 이자소득세가 없고 농어촌특별세 1.4%만 내요. 조합원이나 준조합원(출자금을 내고 가입)이어야 해요. 3,000만 원을 넘는 부분은 일반 15.4%예요.
> - 총급여 7,000만 원을 넘는 준조합원은 2026년에 생긴 이자에 5%, 2027년부터 9%가 붙어요. 이 계산기에는 넣지 않았어요.
> - **비과세**: 세금이 없어요. 청년도약계좌, ISA 한도 내 이익 등이 해당됩니다.

위치: 입력 폼 위에 접이식(`<details>`)으로 두고, 처음 방문 시 펼쳐진 상태(`open`).

## 7. 파일 구조

```
apps/savings-calculator/
├── spec.md       ← 이 계획서
├── index.html    ← 화면 구조, 사용법·면책 문구, 테마 초기화 인라인 스크립트
├── style.css     ← 앱 전용 스타일 (색은 모두 블로그 CSS 변수 사용)
└── app.js        ← 입력 처리, 쉼표 포맷, 계산 함수, 결과 표시, 테마 토글
```

- **외부 라이브러리 없음** (CDN도 사용하지 않음). 순수 HTML/CSS/JS.
- `app.js` 안의 계산 함수는 화면 코드와 분리된 **순수 함수** `calculate({type, amount, months, rate, method, taxCode})`로 만든다. → Review 단계에서 `node`로 예시 A~D를 바로 검증할 수 있게 하기 위함 (파일 끝에 `if (typeof module !== 'undefined') module.exports = { calculate };`).
- 빌드: `build.js`가 `apps/` 폴더를 `dist/apps/`로 그대로 복사하므로 별도 빌드 작업 없음. `dist/css/style.css`도 복사되므로 상대 경로 `../../css/style.css`가 배포본에서도 동작한다.

## 8. 색상·테마

### 블로그 색상 참조 방식

| 방법 | 장점 | 단점 |
|---|---|---|
| **A. `../../css/style.css` 링크** | 블로그 색을 바꾸면 앱도 자동 반영. 다크 모드 정의(`[data-theme="dark"]`, `prefers-color-scheme`)를 그대로 재사용 | 블로그의 헤더·본문 등 다른 스타일도 같이 불러옴 (클래스 이름만 겹치지 않으면 문제 없음) |
| B. 변수 값 복사 | 앱이 완전히 독립 | 블로그 색이 바뀌면 앱만 옛 색으로 남음. 다크 모드 정의 중복 |

**선택: A (블로그 style.css 링크)**. CLAUDE.md의 "style.css의 CSS 변수를 참조할 것" 규칙에 가장 잘 맞는다.
- `index.html`에서 `../../css/style.css`를 먼저, 그다음 앱 `style.css`를 링크.
- 앱 CSS 클래스는 모두 `sc-` 접두사(예: `.sc-tab`, `.sc-result`)를 붙여 블로그 스타일과 충돌을 피한다.
- 앱 `style.css`에는 색상 hex 값을 직접 쓰지 않는다. `--color-bg`, `--color-surface`, `--color-text`, `--color-text-secondary`, `--color-accent`, `--color-accent-hover`, `--color-border`, `--color-tag-bg`, `--color-tag-text`만 사용. (예외: 오류 문구 빨간색 1개는 앱 안에서 변수로 정의)

### 다크 모드 연동

블로그는 `localStorage`의 `theme` 키(`'light'`/`'dark'`)를 `<html data-theme>`에 반영한다. 같은 도메인이라 앱에서도 같은 값을 읽을 수 있다.

1. `index.html` `<head>`에 블로그와 **똑같은** 인라인 스크립트를 CSS 링크보다 먼저 둔다(깜빡임 방지):
   ```html
   <script>
     (function(){ var t = localStorage.getItem('theme');
       if (t) document.documentElement.setAttribute('data-theme', t); })();
   </script>
   ```
2. 저장값이 없으면 `data-theme`을 설정하지 않아 블로그 CSS의 `prefers-color-scheme` 규칙이 시스템 설정을 따른다.
3. 헤더에 테마 토글 버튼(🌙/☀️)을 두고, 블로그 `js/theme.js`와 같은 방식(클릭 시 `data-theme` 변경 + `localStorage.setItem('theme', …)`)으로 동작. → 앱에서 바꾼 테마가 블로그에도 유지된다.
   - `js/theme.js`를 `../../js/theme.js`로 불러와 재사용해도 된다(버튼 id `theme-toggle`만 맞추면 됨). **선택: 재사용** (코드 중복 방지). 단, 블로그 파일은 수정하지 않는다.

## 9. 블로그 연동 (Embed 단계용)

`apps.json`에 추가할 항목 초안:

```json
[
  {
    "path": "apps/savings-calculator/",
    "emoji": "💰",
    "title": "적금·예금 이자 계산기",
    "description": "금액·기간·금리만 넣으면 단리/월복리, 세금(15.4%·비과세·세금우대)까지 반영한 만기 세후 수령액을 바로 계산해요."
  }
]
```

- `build.js`의 `buildAppsHtml()`이 `base + path`로 링크를 만들므로 `path`는 앞에 `/` 없이 쓴다 → `/apps/savings-calculator/`.
- 필요하면 관련 글(파킹통장·청년도약계좌 글)에서 계산기로 링크하는 것은 Embed 단계에서 사용자에게 따로 확인한다(이번 범위 아님).
