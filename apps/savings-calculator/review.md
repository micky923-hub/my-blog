### Build가 일부러 정한 사항 평가

| 결정 | 평가 | 이유 |
|---|---|---|
| 돌아가기 링크 `../../` (spec은 `/`) | **수용** | `basePath`가 `/`인 지금은 `/`와 같은 곳으로 갑니다(실제 확인). 나중에 basePath가 바뀌거나 하위 경로에 배포해도 그대로 동작하고, CSS·JS·favicon과 같은 상대 경로 방식이라 일관됩니다. 앱이 `/apps/savings-calculator/`(끝 슬래시 포함)로 열린다는 전제는 CSS 경로에도 똑같이 적용되고, apps.json의 `path`도 슬래시로 끝나므로 문제없습니다 |
| 금액 12자리 제한 | **수용** | 최대값(적금 9,999억 원 × 120개월 × 20% 월복리)도 결과가 안전 정수(2^53) 범위 안이라 원 단위 정확도가 보장됩니다. 실사용에 충분히 큰 범위입니다. `calculate()`의 "9,999억 원 이하" 문구는 입력칸이 12자리로 잘리기 때문에 화면에는 나오지 않습니다 |
| 오류 문구는 `--color-text`, 빨강은 테두리·아이콘에만 | **수용(오히려 좋음)** | `#dc2626` 글씨는 다크 배경(#18181b)에서 대비가 약 4:1로 본문 기준(4.5:1)에 못 미칩니다. 글씨는 테마 변수로 두고 빨강은 강조에만 쓴 편이 두 테마 모두에서 읽기 좋습니다(스크린샷 08 확인) |
| 기본값을 예시 A로 채움 | **수용** | 처음 들어오자마자 결과 예시가 보여 사용법을 바로 알 수 있습니다. spec 6장 화면 구성도의 값과 같고, 값을 지우면 안내 문구로 바뀝니다 |
| 모든 폭에서 1단 | **수용** | spec 6장에서 2단은 "선택"이었습니다. 680px 폭에서 1단도 1280px 스크린샷상 어색하지 않고, 위에서 아래로 "입력 → 결과" 순서가 분명합니다 |

## 발견한 문제와 수정 내역

### [수정] 쉼표 바로 뒤에서 Backspace(쉼표 바로 앞에서 Delete)를 누르면 아무것도 지워지지 않음

- **현상**: `19,234,567`에서 커서를 `19,|234,567`에 두고 Backspace를 누르면 쉼표만 지워집니다. 그런데 곧바로 쉼표가 다시 붙어 값이 그대로입니다. 사용자는 키가 먹지 않는다고 느낍니다. Delete 키도 마찬가지입니다.
- **수정 파일**: `apps/savings-calculator/app.js` (화면 코드만, `calculate()`는 변경 없음)
  - `removeDigitNextToDeletedComma(e)` 추가: `input` 이벤트의 `inputType`이 `deleteContentBackward`/`deleteContentForward`이고 지워진 것이 쉼표뿐이면(숫자는 이전 값과 같으면), 커서 앞(Backspace) 또는 뒤(Delete)의 숫자를 대신 지운 뒤 쉼표 포맷을 다시 적용합니다.
  - 이전 값 비교용 `lastAmountValue`를 두고, 직접 입력 후와 빠른 입력 버튼(`setAmount`) 후에 갱신합니다.
- **재검증**: `19,|234,567` + Backspace → `1,234,567`(커서 1). `1|,234,567` + Delete → `134,567`. 빠른 입력 버튼을 누른 뒤에도 똑같이 동작하고, 끝에서 누르는 일반 Backspace도 정상입니다. 계산 테스트를 다시 돌려 모두 통과했고, 브라우저 앱 항목도 모두 통과했습니다.

그 밖에 고쳐야 할 문제는 없었습니다. `index.html`, `style.css`는 변경하지 않았습니다.

## 남은 개선 제안 (MVP 범위 밖, 선택사항)

1. **spec.md 공개 배포**: `build.js`가 `apps/` 폴더를 통째로 복사해서 `dist/apps/savings-calculator/spec.md`(그리고 이 review.md)도 사이트에 공개됩니다. 민감한 내용은 없지만 원하지 않으면 build.js에서 `.md`를 빼고 복사하도록 바꾸는 방안이 있습니다(블로그 파일이라 이번 범위 밖).
2. **오류 안내 읽기 빈도**: 결과 영역 전체가 `aria-live`라 입력할 때마다 스크린리더가 결과를 다시 읽을 수 있습니다. 세후 수령액과 오류 문구에만 live 영역을 두면 덜 번잡합니다.
3. **이자율 칸 maxlength 5**: "20.00"까지는 입력되지만 "12.345" 같은 붙여넣기는 잘려 "12.34"가 됩니다. 의도한 동작과 맞지만, 붙여넣은 값이 잘렸다는 안내는 없습니다.
4. **은행식 세금 계산 옵션**: 소득세·지방소득세를 따로 계산하고 10원 미만을 버리는 방식을 선택할 수 있게 하면 실제 통장 금액에 더 가까워집니다(현재는 면책 문구로 안내 중).
