- 월세 효과: 다른 특별세액공제가 13만 원 이상(교육비 100만)일 때 6,000만·720만 → 1,188,000 = credit × 1.1. 13만 원 미만(보험 100만 → 12만)이면 1,177,000으로 표준세액공제만큼 작아지는 것이 맞다.

## 4. "12월 31일 전에 하면" 상자 — 통과 + 수정 1건

- 각 줄 금액은 `calculate()`를 바꾼 입력으로 다시 돌린 값과 같다(1장 비교에 포함).
- 결정세액 한도: 예시 1에서 연금 +325,500(원래 효과 1,485,000보다 작음)과 "낼 세금이 적어 일부만 돌려받아요" 문구가 보임. 예시 8(결정세액 0원)은 목록 대신 "이미 0원이라…" 문구가 보임. 과장 없음.
- `?date=2027-01-05`: 제목이 "아직 서류로 챙길 수 있는 것"으로 바뀌고 금액 목록이 숨고 서류 목록이 보임.
- 혼인: "올해 결혼했거나 결혼 예정" 체크 시에만 혼인 칸·줄이 보이고 "+550,000원", "모두 하면 … (혼인신고 제외)".
- **수정**: 카드 문턱은 넘었지만 바꿔도 공제가 늘지 않는 경우(카드 공제 한도를 이미 채움 — 예시 14, 또는 문턱 위 지출이 이미 모두 체크카드 — 예시 9·10) "+0원"만 덩그러니 보였다. `app.js` `renderActions`에 "바꿔도 카드 공제가 늘지 않아요(한도를 채웠거나 문턱 위 지출이 이미 체크카드예요)" 문구 분기를 추가했다. 계산 함수는 건드리지 않음.
- spec 4장 "연금 줄에 월 환산" 표시는 구현되지 않았다. 연말까지 남은 개월 수 기준이 정해지지 않아 넣지 않았고, 연금 계산기 링크로 대신한다(사용자 판단 사항, 아래 질문 3).

## 5. 화면·접근성 — 통과

- `npm run build` 후 `dist`를 포트 8767로 열어 Playwright로 확인, 끝난 뒤 서버 종료.
- 320px·375px·1280px × 라이트·다크 6장: 가로 스크롤 없음(scrollWidth = 창 폭), 화면 밖으로 나간 요소 없음, NaN 없음, 콘솔 오류 0건. 다크 모드 색 대비 정상.

- 입력: "30,000,000원" 붙여넣기 → 30,000,000, 16자리 입력 → 12자리로 자름, 총급여 빈칸 → 오류 문구, 개월 13 → 오류, 70세 이상 인원 초과 → 오류.

## 6. 문구 — 통과

- 사용법(`<details open>`)·면책·"이렇게 계산해요"·FAQ 6개가 쉬운 말. 예시 숫자(37,750,000 / 30,116,332 / 3,257,449 / 2,017,440 / 530,820)가 계산 결과와 같음.
- FAQ 화면 문구와 JSON-LD가 질문·답 모두 글자까지 같음(스크립트 비교). meta description = JSON-LD description.
- FAQ 6 분납: spec대로 "확인 못 하면 회사에 물어보세요"로 바뀌어 단정하지 않음.
- 보험사·상품 이름, 상담·전화·카카오톡 연락처 없음. 외부 링크·CDN 없음(og:image Unsplash 주소만, 기존 앱과 같음).
- 참고 ①: JSON-LD WebApplication `name`이 "연말정산 환급 계산기"로 spec 8장("…예상 계산기")과 다르지만, 맨 위 사용자 결정(앱 이름 "연말정산 환급 계산기")을 따른 것이라 그대로 둠. apps.json 등록(Embed) 때도 이 이름을 쓰면 됨.
- 참고 ②: 월세 8,000만 원 초과 안내 "현금영수증 소득공제로 받을 수 있어요"는 spec·월세 계산기 문구와 같음.

## 7. 코드 품질 — 통과

- 빈칸 → 0(기납부·4대보험은 "입력 안 함"), 0·음수·소수·12자리 초과 → 오류 문구, 999,999,999,999 → 안전 정수 범위 안, NaN·Infinity 없음.
