## 1. 앱 개요

- **누가**: 회사에서 연말정산을 하는 직장인(근로소득만 있는 사람). 블로그의 연말정산·막판 체크리스트·맞벌이·카드·월세 글 독자.
- **언제**: 10~12월("12월 31일 전에 뭘 하면 더 받지?"), 1~2월("나 얼마 돌려받지? 토해 내나?").
- **왜**: 총급여·가족·카드·연금·월세만 넣으면 1~3분 안에 ① **환급 또는 추가 납부 예상액**, ② 항목별로 줄인 세금, ③ **12월 31일 전에 할 수 있는 행동과 그 금액**을 한 화면에서 본다.

### 이 계산기만의 차별점

1. **행동 목록에 금액이 붙는다.** "연금계좌 300만 원 더 넣으면 +396,000원", "남은 지출 100만 원을 체크카드로 쓰면 +24,750원"처럼 계산기를 다시 돌린 값을 보여 준다. 결정세액이 0원이면 "더 챙겨도 늘지 않아요"라고 솔직하게 알려 준다.
2. **"다 하면 +얼마"** 를 한 번에 다시 계산한다. 항목별 금액을 단순히 더하지 않아서 결정세액 한도·세율 구간 변화가 반영된다.
3. **월세·연금 계산기와 숫자가 같다.** 같은 기준(지방소득세 포함)으로 만들고, 차이가 나는 이유(표준세액공제 13만 원)를 화면에 설명한다.

### 범위 밖 (화면에 한 줄로 안내)
- 사업·프리랜서·금융소득 등 다른 소득이 있는 사람(5월 종합소득세 신고 대상) → [프리랜서·부업 종합소득세 신고 가이드] 링크.
- 중도 입사·퇴사, 두 회사 이상 근무(전 직장 원천징수영수증 합산), 외국인, 중소기업 취업자 소득세 감면.

1. **근로소득공제** `E = min(floor(구간 기준액 + (S − 초과 기준) × % / 100), 20,000,000)` → **근로소득금액** `W = S − E`
2. **4대보험(자동)**, 월 보수 `m = S / 12`(소수 유지):
   - 국민연금 `np = floor(clamp(m, 40만, 637만) × 475/10000) × 6 + floor(clamp(m, 41만, 659만) × 475/10000) × 6`
   - 건강 `hm = floor(m × 3595/100000)`, 장기요양 `lm = floor(hm × 1314/10000)`, 고용 `em = floor(m × 9/1000)` → `(hm + lm + em) × 12`
   - "더 자세히"에 합계를 넣으면 그 값을 그대로 쓴다(국민연금·건강·고용 모두 전액 소득공제라 나눌 필요 없음).
3. **인적공제** `P = 150만 × (1 + 배우자 + 자녀8~20 + 자녀7이하 + 부모 등) + 100만 × 70세이상 + 200만 × 장애인`
4. **카드 공제**
   - 총급여 7,000만 원 초과면 문화체육 사용액을 신용카드에 더한다(30% 대상 아님).
   - 문턱 `th = floor(S × 25/100)`을 **신용카드 → 체크·현금 → 문화체육 → 전통시장·대중교통** 순서로 뺀다(블로그 글 "신용카드부터 먼저 채운 것으로 계산"과 같음).
   - `gross = floor(신용' × 15%) + floor(체크' × 30%) + floor(문화' × 30%) + floor(시장' × 40%)`
   - 기본 한도 `L1 = (S ≤ 7,000만 ? 300만 : 250만) + 자녀 추가(자녀 수 = 8~20세 + 7세 이하; 1명·2명 이상)`
   - 추가 한도 `L2 = S ≤ 7,000만 ? 300만 : 200만`, 추가 대상 `X = floor(시장' × 40%) + floor(문화' × 30%)`
   - `cardDed = min(gross, L1) + min(max(gross − L1, 0), L2, X)`
5. **과세표준** `B = max(0, W − P − 4대보험 − cardDed)`
6. **산출세액** `T = floor(B × 세율/100) − 누진공제` (해당 구간, 경계 "이하")
7. **세액공제**
   - 근로 `ec = T ≤ 130만 ? floor(T × 55%) : 715,000 + floor((T − 130만) × 30%)` → 2.3 한도 공식(곱·나눗셈 결과 `floor`)과 비교해 작은 값
   - 자녀 `n = 8~20세 자녀 수`: 0 → 0, 1 → 25만, 2 → 55만, 3명 이상 → 55만 + 40만 × (n − 2) / 출산·입양 30·50·70만
   - 연금 `elig = min(min(연금저축, 600만) + IRP, 900만)`, `pc = floor(elig × (S ≤ 5,500만 ? 15 : 12) / 100)`
   - 월세 `S ≤ 8,000만`이면 `floor(min(월세, 1,000만) × (S ≤ 5,500만 ? 17 : 15) / 100)`, 아니면 0(+ 이유 "총급여 8,000만 원 초과")
   - 특별세액: 보험 `floor(min(보험, 100만) × 12%)` / 의료 `t3 = floor(S × 3%)`, `기타대상 = min(max(기타 − t3, 0), 700만)`, `본인대상 = max(본인등 − max(t3 − 기타, 0), 0)`, `floor((기타대상 + 본인대상) × 15%)` / 교육 `floor(교육 × 15%)` / 기부 `floor(min(기부, 1,000만) × 15%) + floor(max(기부 − 1,000만, 0) × 30%)`
   - **표준세액공제**: `특별세액 합 + 월세 ≥ 13만`이면 특별세액·월세를 쓰고 표준 0, 아니면 특별세액·월세를 버리고 **표준 13만**(= 둘 중 큰 쪽)
   - 고향사랑 `g = min(기부, 2,000만)`: `floor(min(g,10만) × 100/110) + floor((min(g,20만) − 10만)⁺ × 40%) + floor((g − 20만)⁺ × 15%)`
   - 결혼 50만
8. **결정세액** `D = floor10(max(0, T − 세액공제 합))`, 지방소득세 `DL = floor10(D × 10%)`, 합계 `DT = D + DL`
   - 세액공제 합이 T보다 크면 `lost = 합 − T`(못 받는 공제)를 보여 준다.
9. **환급/추가 납부** (기납부 `G` 입력 시): `GL = floor(G × 10%)`, `refund = (G + GL) − DT` (양수 환급, 음수 추가 납부, 0이면 "딱 맞아요")
   - 월 소득세 탭: `G = 월 소득세 × 개월 수(1~12)`
10. **할 일 Δ**: `Δ = DT(현재) − DT(바꾼 입력)` — 같은 `calculate()`를 바꾼 입력으로 다시 호출. 연금: `IRP += room` / 카드: `move = min(X, 신용카드)`만큼 신용→체크 / 고향사랑: `max(현재, 10만)` / 모두: 세 가지 동시 / 혼인: `marriage = true`.
11. **항목별 효과**: 해당 입력(또는 공제)을 0으로 놓고 다시 계산한 `DT − 현재 DT`. 근로소득세액공제는 `ec` × 1.1 근사 대신 같은 방식(ec를 0으로)으로 계산하려면 내부 옵션 `{disable: 'earnedCredit'}`을 둔다.

- 반올림: 중간값 모두 원 미만 **버림**, 결정세액·지방소득세 **10원 미만 버림**(국고금 끝수 처리 관행 → **확인 필요**). 연금 계산기의 `Math.round(eligible × 165/1000)`와는 금액이 만 원 단위일 때 같고, 끝자리가 있으면 수십 원까지 다를 수 있다(12장).
- 소수(`0.15`)를 곱하지 않고 `× 15 / 100` 정수 연산 후 `floor`(부동소수점 오차 방지). 최대 입력 999,999,999,999원에서도 `Number.MAX_SAFE_INTEGER` 안.

> **예시** 총급여 5,000만 원, 1인 가구, 신용카드 1,500만·체크카드 300만 원, 연금저축 300만 원, 이미 낸 소득세 250만 원 (검산 예시 2)

> - 과세표준: 37,750,000 − 인적 1,500,000 − 4대보험 4,858,668 − 카드 1,275,000 = **30,116,332원**
> - 산출세액: 30,116,332 × 15% − 1,260,000 = **3,257,449원**
> - 결정세액: 3,257,449 − 근로 660,000 − 연금 450,000 − 표준 130,000 = **2,017,440원**(지방소득세 201,740원)
> - 환급액: 2,750,000 − 2,219,180 = **530,820원**
>
> **실제 연말정산과 다를 수 있어요**: 4대보험료는 총급여로 추정해요 / 원 단위 끝수 처리로 수십 원 차이가 날 수 있어요 / 주택자금 공제·감면은 넣지 않았어요.

## 9. 테스트 케이스 (Review에서 원 단위까지 일치)

### 예시 1 — 총급여 3,000만, 1인, 신용 900만·체크 300만, 기납부 60만

- 카드: 문턱 750만 → 신용 150만×15% = 225,000 + 체크 300만×30% = 900,000 → **1,125,000**
- 과세표준 **14,709,792** → 산출 14,709,792×15% − 126만 = **946,468**
- 근로세액공제 946,468×55% = 520,557(한도 74만 안) / 표준 130,000
- 결정세액 **295,910**, 지방 29,590, 합계 325,500
- 환급 = (600,000 + 60,000) − 325,500 = **334,500**
- 할 일: 연금 900만 채우기 **+325,500**(결정세액 한도에 걸림: 원래 효과 1,485,000) / 카드 100만 전환 +11,150 / 고향사랑 +100,000 / 모두 **+325,500**

## 12. 기존 계산기와 숫자 일치 점검 방법 (Review용)

1. **연금저축·IRP 계산기**: 결정세액이 충분한 입력(예: 총급여 5,000만·8,000만, 다른 공제 기본)에서
   `Δ = calculate(연금 0).decidedTotal − calculate(연금 X).decidedTotal` 이 `pension-tax-calculator/app.js`의 `calculate({incomeType:'salary', income, pension, irp}).refund`와 같아야 한다.
   - 확인된 값: 5,000만·연금저축 600만 → **990,000 = 990,000**, 8,000만·연금저축 600만에 IRP 300만 추가 → **396,000 = 396,000**.
   - 끝자리가 있는 금액(예: 1,234,567원)은 연금 계산기는 반올림(203,704), 이 앱은 버림·10원 절사라 **수십 원 이내 차이 허용**. 이 허용을 Review 기준으로 명시한다.
   - 결정세액 한도에 걸리는 입력(예시 1·5·8)에서는 이 앱이 더 작게 나오는 것이 맞다(연금 계산기는 안내 문구로만 처리).
2. **월세 세액공제 계산기**: `rent-tax-credit-calculator/app.js`의 `credit`(소득세 기준 17%·15%)이 이 앱 `credits.rent`와 **원 단위까지 같아야** 한다(예: 4,000만·720만 → 1,224,000). 결정세액 효과는 표준세액공제 13만 원 때문에 다를 수 있으며, 다른 특별세액공제가 13만 원 이상이면 `credit × 1.1`과 같아야 한다.
3. **블로그 글 숫자**: 막판 체크리스트 51행(600만 추가 99만), 81행(체크카드 300만 → 약 7만 4천 원: 총급여 5,000만, 신용 1,800만을 신용 1,500만·체크 300만으로 바꾸면 Δ = **74,250**, 작성자 계산 확인), 고향사랑 20만 → 약 14만 4천 원(예시 11)을 `actions()`로 재현.
4. Review는 두 기존 앱의 `app.js`를 `require`해서 위 비교를 스크립트로 돌리고 결과를 review.md에 붙인다(기존 앱 파일은 읽기만 하고 고치지 않는다).
