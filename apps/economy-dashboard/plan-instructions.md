## 사용자와 합의된 내용
- 경제 블로그 "Financial Diary"에 **매일 아침 한 곳만 보면 되는 "생활경제 대시보드"** 를 만든다. 재방문 유도가 목적.
- **날씨×장바구니(weather-economy)를 이 대시보드 안의 한 칸으로 합친다.**
- 실시간 시세는 하지 않는다(거래소 데이터 재배포 라이선스, 정적 사이트 구조). **전일·최근 발표 기준** 지표 + 날짜·출처 표기.
- 차별점: 지표마다 **"그래서 내 지갑엔?"** 한 줄과 블로그의 **계산기·관련 글 링크**. 예) 기준금리·대출금리 → 대출 갈아타기 계산기 / 환율 → "100만 원 환전 시 지난주보다 ○원" + 환전 계산기 / 물가 → 장바구니 시세 / 코스피 → 지수·등락만.
- **투자 권유 금지**: 종목 추천, "사세요/파세요", 매수·매도 신호, 전망 단정 금지. 사주·운세 없음. 매일 자동 블로그 글 생성 없음.
- 브라우저는 외부 API를 직접 부르지 않는다. 키는 GitHub Secrets에만. 수집 실패해도 배포·블로그는 멈추지 않는다(`continue-on-error`, 항목별 독립 실패, 이전 배포본 재사용).

## 반드시 결정·제안할 것 (추천안과 이유)
1. **합치는 구조**: (a) 대시보드 하나의 수집 스크립트가 모든 데이터를 받음, (b) 각 수집 스크립트는 그대로 두고 대시보드가 여러 JSON(`weather-economy/data.json`, `exchange-fee-calculator/rates.json`, 새 `economy-dashboard/data.json`)을 읽음 등. CLAUDE.md "앱은 자기 폴더 안에 자체 완결" 규칙과의 관계, 기존 weather-economy 앱 페이지를 남길지/대시보드로 리다이렉트할지/폴더를 옮길지, 환전 계산기 영향(건드리지 않는 쪽 선호)을 비교해 추천.
2. **화면 구성**(모바일 우선): 맨 위 "오늘의 한 줄 요약", 지표 카드 순서, 날씨×장바구니 칸의 위치와 축약 정도, 카드마다 숫자·변화·기준일·출처·"내 지갑엔" 한 줄·관련 계산기/글 링크. 데스크톱 배치.
3. **지표 목록 1차/2차 구분**: 1차는 키 부담이 적고 신뢰도 높은 것 위주로 6~10개.
4. **메인 화면 노출**: 아이콘 줄 등록(규칙 그대로) vs 메인 위쪽 요약 띠. 이전 결정(커밋 a5c02aa, 첫 화면에 글이 보이도록 위쪽 축소)과 weather-economy spec 4-2의 A/B/C안 논의를 참고. 아이콘 줄 제목이 "무료 계산기"인 문제도 다뤄라.
5. **배포 일정**: 기존 cron(평일 11:30/15:30, 매일 06:20/18:20)으로 충분한지, 지표별 발표 시각과 맞는지. cron 추가는 최소화.
6. **기록 누적**: weather-economy의 "이전 배포본 이어붙이기" 방식을 지표에도 쓸지, 스파크라인(작은 추이 그래프)을 1차에 넣을지.
7. **"내 지갑엔" 문구 규칙**: 규칙 기반 템플릿, 단정 금지, 금지어 목록(weather-economy spec 5-3 원칙 확장).
