## Builder가 보고한 계획 이탈 평가

| 이탈 | 평가 |
|---|---|
| 국고채 3년·10년 수집일이 다르면 **더 이른 날** | **수용.** 한 줄로 두 값을 표시하므로, 더 이른 날을 쓰면 "이 날 이후에 받은 값"이라는 말이 두 값 모두에 맞다. 계획서 4-2의 "사실과 다른 날짜를 쓰지 않는다"는 취지와 맞는다. 테스트(`2026.10.7.`)로 확인 |
| 날짜가 없으면 끝 점도 뺌 | **수용.** 계획 4-2는 "`, 날짜` 부분을 뺀다"이고, 끝 점은 `YYYY.M.D.` 날짜 형식의 일부라서 날짜와 함께 빠지는 게 맞다. `출처 : ECOS(…)`로 자연스럽다 |
| `validateDataJson(data, nowMs)` 인자 추가, 스크립트가 `--now` 전달 | **수용.** 5장 "미래가 아니면 사용"을 테스트 가능하게 만든 것이다. 인자를 생략하면 지금 시각을 쓰므로 기존 호출(`renderApp(raw)`)은 그대로 동작한다. 스크립트 `opts.today`와 검증 기준일이 같은 `nowMs`에서 나와, `--now`로 실행해도 새 값의 fetchedAt이 잘리지 않는다 |
| 키·한도 오류나 연속 접속 실패로 수집이 멈추면 `StatisticTableList`를 건너뜀 | **수용.** 계획서는 "수집 뒤·실패 무시"이고, 멈춘 원인(키 무효·한도 초과·네트워크 단절)이 그대로면 meta 호출도 실패할 게 뻔하다. 건너뛰면 한도만 아끼고 지표에는 영향이 없다. 로그에 `수집이 중간에 멈춰 통계표 정보 확인은 건너뜀`이 남고, `spec.md` 부록 C에도 적혀 있다 |
| 하단 "자료" 문단을 p + ul + p로 나눔 | **수용.** 문구는 4-3과 글자까지 같다. 항목 목록이라 의미상 `ul`이 맞고, 320px에서 더 잘 읽힌다(스크린샷 확인). 새 스타일은 `.ed-footnote-list`뿐이고 변수 밖 색은 없다 |

## 배포 후 확인할 것

1. Actions "Fetch economy indicators (BOK ECOS)" 첫 실행 로그의 `[meta]` 줄
   - `통계표명 … ≠ 고정 표`가 나오면 `app.js` `ED_DEFS`의 `statName`을 고친다. fixture로는 CPI가 `소비자물가지수(2020=100)`처럼 다를 수 있음을 확인했다. 실제 이름에 이 괄호가 붙어 있으면, 화면에서 그대로 쓸지 뺄지 결정해야 한다.
   - `ORG_NAME="…"`에 값이 나오면 계획서 7-1(원/달러·국고채 원작성기관) 수동 확인 결과와 대조한다.
2. 배포된 페이지에서 출처 줄 날짜가 수집일(KST)로 나오는지, 이전 배포본을 재사용한 카드는 예전 날짜로 남는지 확인한다.
3. 계획서 7-1 수동 확인이 끝나면 `ED_DEFS`의 `org` 한 줄과 `index.html` 하단 목록을 함께 고친다(테스트 `출처 문구` 단언도 함께).

## 남은 제안 (이번 범위 밖, 선택)

1. `mask`는 키와 API 주소를 가리지만, 응답 MESSAGE에 `/json/kr/` 글자만 따로 들어오면 그대로 남는다. 실제 ECOS 응답에서 이런 일은 거의 없고 키도 새지 않지만, "0건" 기준을 엄격히 지키려면 `/(json|xml)/kr/…` 조각도 가리는 한 줄을 추가할 수 있다(기존 코드에도 있는 동작).
2. meta 단계에서 키·한도 오류가 처음 나면 남은 통계표 호출도 멈추게 하면 최대 5회를 아낄 수 있다(지금은 계획서대로 "무시하고 다음으로").
3. 국고채에서 한쪽만 fetchedAt을 모르고 generatedAt도 없으면 다른 쪽 날짜가 쓰인다. 실제로는 스크립트가 항상 fetchedAt이나 generatedAt을 채우므로 생기지 않는 조합이다.
4. 계획서 4-5 메모(KAMIS 이용 조건 표기, 기상청·수출입은행 형식 맞추기)는 다음 작업에서 사용자가 판단할 일이다.
