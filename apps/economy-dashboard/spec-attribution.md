## 1. 개요

| 항목 | 내용 |
|---|---|
| 무엇을 | ECOS 지표 7개의 출처를 한국은행 권장 형식 `출처 : ECOS(작성기관, 통계표명), YYYY.M.D.` 로 **카드마다** 표시하고, 하단 "자료" 문단에 원작성기관을 구분해 적는다 |
| 왜 | 한국은행 안내: 한국은행 작성 통계는 출처만 밝히면 상업적 이용 가능, **ECOS 안의 타 기관 통계는 원작성기관 조건을 따른다**. 이 블로그는 광고가 있어 상업적 용도에 해당 |
| 방식 | 사용자 선택 A **"표기만 정확히"** — 지표는 7개 모두 유지, 표기만 고친다. 숫자 계산·카드 순서·수집 주기는 바꾸지 않는다 |
| 범위 밖 | 기상청·KAMIS·수출입은행 표기(7장 메모만), 다른 앱, 블로그 공용 파일 |

### 2-1. 소비자물가(국가데이터처) 이용 조건 — 확인됨(사용자 확인, 2026-10-09)
사용자가 KOSIS 「통계정보 활용약관」·「통계정보 이용지침」 원문에서 확인:

| 항목 | 내용 | 이 앱에 적용 |
|---|---|---|
| 출처표시 의무 | 활용약관 **제7조**: 활용 시 제공기관에서 제공된 정보임을 표시 | 카드 줄과 하단 문단에 "국가데이터처"를 이름으로 적어 충족 |
| 이용 범위 | 통계청(국가데이터처) 자료는 일반적으로 **공공누리 제1유형**: 출처만 밝히면 상업적 이용·2차적 저작물(분석·차트 등 가공) 자유 | 광고 있는 블로그 OK. 전년동월비 계산·스파크라인은 허용되는 가공 |
| 금지 | 가공 없이 다운로드한 그대로 **유료 판매**. 북한통계·국제통계는 비상업적 목적만 | 해당 없음(무료 표시, CPI는 일반 국내 통계) |
| 권장 표기 예 | "출처: 국가통계포털(KOSIS)" | 아래 결정 |

**표기 결정**
- 카드: `출처 : ECOS(국가데이터처, 소비자물가지수), 2026.10.9.` — **KOSIS는 카드에 쓰지 않는다.**
- 하단 문단: `원작성: 국가데이터처(옛 통계청) — 소비자물가지수 (공공누리 제1유형 · 출처 표시)` (4-3).
- 이유
  1. 숫자는 **KOSIS가 아니라 ECOS에서 받는다.** "출처: KOSIS"라고 쓰면 받은 경로가 사실과 달라진다. KOSIS 예시는 KOSIS에서 받았을 때의 예시다.
  2. 제7조가 요구하는 것은 **제공기관(국가데이터처) 표시**다. `ECOS(국가데이터처, …)`가 원작성기관 이름을 밝히므로 ECOS 권장 형식과 KOSIS 출처표시 의무를 한 줄로 함께 충족한다.
  3. 공공누리 표기를 카드마다 넣으면 모바일(320px)에서 줄이 넘친다 → 하단에 한 번만(지금 기상청 표기와 같은 방식).
  4. 가공 사실은 기존 면책 "ECOS 지수로 계산해 … 발표와 0.1%p 다를 수 있어요"로 이미 밝힌다(통계청 → 국가데이터처(옛 통계청)만 수정). 원 발표 수치를 바꿔 쓴 것으로 오해되지 않게 한다.

- **미확인 기관은 화면에 지어내 쓰지 않는다.** 작성기관 칸을 비우고 통계표명만 쓴다. 사용자가 7-1 방법으로 확인하면 고정 표 한 줄만 고친다.
- 통계표명은 위 표(기억·검색 기반)로 고정하되, 첫 실행 로그(4장)로 실제 이름과 맞춰 고친다. 화면에는 ECOS 번호 체계(`4.2.1.` 같은 앞 번호)를 뺀 이름을 쓴다.

## 3. 작성기관을 얻는 방법 — 결정: **코드에 고정한 표 + 실행 로그로 확인**

### 3-1. 조사 결과
| 항목 | 내용 | 상태 | 출처 |
|---|---|---|---|
| 서비스 주소 | `https://ecos.bok.or.kr/api/StatisticTableList/{인증키}/json/kr/{시작}/{끝}/{통계표코드}` (마지막 코드 넣으면 1건만) | 확인됨(2곳) | ecos-go 문서 `docs/api/통계표목록.md`, R `ecos` 패키지 `statTableList(stat_code)` NEWS |
| 응답 필드 | `P_STAT_CODE`, `STAT_CODE`, `STAT_NAME`, `CYCLE`, `SRCH_YN`, **`ORG_NAME`(출처)** | 확인됨(ecos-go 문서 + 구조체 정의, 같은 저자 2곳) / 공식 문서 미확인 | ecos-go (pkg.go.dev, GitHub raw) |
| `ORG_NAME` 값 | **대부분 `null`.** 실측 834건 중 1건만 값 있음(`102Y001` → 한국은행) | 미확인(제3자 실측 1곳) | ecos-go 문서 |
| `StatisticSearch` 행의 `STAT_NAME` | 데이터 행에 통계표명이 같이 올 것으로 **추정** | 미확인 | — (지금 fixture에는 `ITEM_NAME1`만 있음) |

### 3-2. 결정과 이유
| 선택지 | 판단 |
|---|---|
| A. API `ORG_NAME`을 받아 화면에 쓰기 | **안 함.** 거의 항상 비어 있다고 함 → 결국 대비책이 본체가 된다. 값이 바뀌어도 사람이 확인하지 않은 기관명이 화면에 나갈 위험 |
| **B. 고정 표(사람이 확인한 값) + 로그로 대조** | **채택.** 출처 문구는 법적 의미가 있어 "확인한 값만" 보여 주는 게 맞다. 7개뿐이라 관리 부담 작다 |

- 고정 표 위치: `app.js`의 `ED_DEFS`(수집 스크립트도 이미 이것을 읽는다)에 지표마다 `stat`, `statName`, `org` 추가. `org`가 `null`이면 "미확인".
- 로그 대조(화면에는 안 씀):
  1. `StatisticSearch` 응답 행에 `STAT_NAME`이 있으면 `[meta] 901Y009 통계표명 "4.2.1. 소비자물가지수" = 고정 표` 또는 `≠ 고정 표 "…"` 한 줄. **추가 호출 0.**
  2. 지표 수집이 모두 끝난 **뒤** 통계표 6개(817Y002 한 번)에 `StatisticTableList/…/{코드}` 1회씩 → `[meta] 731Y001 ORG_NAME=null` 또는 `="…"`. 실행당 +6회(하루 4회 실행 → +24회). 실패·한도 오류는 무시하고 다음으로(지표 데이터에 영향 없음, 즉시 중단 코드여도 이미 수집 완료 후).
- 실패 시 동작: 출처 줄은 **항상 고정 표로 만든다** → API가 무엇을 주든 화면은 같다. 고정 표에서 `org` 없음 → `ECOS(통계표명)`, `statName`도 없음 → `출처 : ECOS, 날짜`.

## 4. 화면 표기 설계

### 4-1. 카드 아래 출처 줄 (ECOS 값으로 그린 카드 7개)
- 지금 `기준·출처 한 줄`(`10월 8일(목) 기준 · 한국은행 ECOS`)을 둘로 나눈다.
  - 1줄: `10월 8일(목) 기준` (+ 이전 값일 때 기존 안내 그대로)
  - 2줄(새, 작은 글씨 `.ed-src`, `--color-text-secondary`): `출처 : ECOS(국가데이터처, 소비자물가지수), 2026.10.9.`
- 국고채 카드는 3년·10년이 한 카드라 줄 1개(같은 통계표).
- 원/달러 카드가 **수출입은행 `rates.json` 대비책**으로 그려질 때는 ECOS 줄을 쓰지 않고 지금처럼 `한국수출입은행 매매기준율`.

### 4-2. 날짜 = **자료를 받아 온 날짜(조회일, KST)** — 결정
| 후보 | 판단 |
|---|---|
| 기준일(자료 날짜) | 이미 1줄에 있음. 중복 |
| **조회일** | **채택.** 한국은행 권장 예시(`…, 2026.10.9.`)가 "언제 ECOS에서 가져왔는지"를 뜻하는 형식이고, 기준일과 따로 보여야 의미가 있다 |

- 값: 지표별 `fetchedAt`(5장). 이전 배포본 값을 다시 쓸 때는 **그 값을 처음 받은 날**이 남는다(오늘 날짜로 바꾸지 않음 — 사실과 다르므로).
- 형식 `YYYY.M.D.` (앞자리 0 없음, 끝 점 포함). 날짜가 없으면 `, 날짜` 부분을 뺀다.

### 4-3. 하단 "자료" 문단 (`index.html` 75행 교체)
```
자료: 한국은행 경제통계시스템(ECOS)

 · 원작성: 국가데이터처(옛 통계청) — 소비자물가지수 (공공누리 제1유형 · 출처 표시)
 · 원/달러 환율(주요국 통화의 대원화환율), 국고채 금리(시장금리(일별))는 ECOS에서 받은 값이며 원작성기관 확인 중
기상청 단기예보(공공데이터포털, 공공누리 제1유형 · 출처 표시), aT KAMIS 농산물유통정보 소매가격, 한국수출입은행 매매기준율.
```

- 한국은행이 아닌 기관은 **"원작성: ○○"** 로 드러낸다. 미확인 2개가 확인되면 해당 줄로 옮긴다.

## 5. 데이터 형식 변경 (`data.json`, `version`은 1 그대로)

| 필드 | 위치 | 값 | 없을 때 (하위 호환) |
|---|---|---|---|
| `fetchedAt` | `indicators.*` | `"2026-10-09"` (KST, 그 지표를 API에서 받은 날) | 파일의 `generatedAt` 날짜를 대신 씀. 그것도 없으면 날짜 없이 표시 |

- 작성기관·통계표명은 **data.json에 넣지 않는다**(고정 표가 앱 코드에 있으므로 중복·불일치 위험만 생김).
- 수집 스크립트: `origin: 'api'`이면 `fetchedAt = 오늘(KST)`. `mergeWithFallback`이 이전 배포본을 쓸 때는 이전 값의 `fetchedAt`을 그대로, 없으면 이전 배포본 `generatedAt` 날짜.
- 앱 검증(`edValidateIndicator`): `fetchedAt`이 실제 날짜이고 미래가 아니면 사용, 아니면 그 필드만 버림(지표는 살림).
- 옛 앱 + 새 data.json: 모르는 필드라 무시 → 문제 없음. 새 앱 + 옛 data.json: 위 "없을 때"대로.

## 9. 승인 요청

1. 작성기관은 **고정 표 + 로그 대조**(API `ORG_NAME`은 화면에 안 씀).
2. 출처 날짜는 **조회일**(지표별 `fetchedAt`), 기준일은 지금 줄에 그대로.
3. 원작성기관 **미확인 2개(원/달러·국고채)는 기관명 없이** `ECOS(통계표명)`로 표시하고 하단에 "확인 중" — 사용자 확인(7-1) 뒤 고정 표 수정.
4. `StatisticTableList` 로그 확인 호출 실행당 +6회(수집 뒤, 실패 무시). 원치 않으면 빼고 7-1 수동 확인만 해도 된다.
