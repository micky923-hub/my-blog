# 연금저축·IRP 세액공제 계산기 — 계획서 (spec)

> 상태: **승인 대기** · 작성일 2026-10-08
> 위치: `apps/pension-tax-calculator/` · 블로그: financialdiary.co.kr
> 첫 번째 앱 `apps/savings-calculator/`의 구조·사용감을 그대로 따른다. CSS 접두사는 **`pt-`**.

---

## 1. 앱 개요

- **누가**: 블로그의 연금저축·IRP·연말정산 글을 읽는 직장인과 개인사업자.
- **언제**: 연말정산 전(특히 10~12월)에 "올해 연금계좌에 얼마 더 넣어야 하지?"가 궁금할 때.
- **왜**: 지금까지 넣은 금액으로 **얼마를 돌려받는지**, 한도까지 채우면 **얼마를 더 받는지**, 한도를 넘겨 **공제받지 못하는 돈**은 없는지 한 화면에서 확인하기 위해.

---

## 2. 세법 기준 (2026년, 블로그 글과 일치)

| 항목 | 기준 |
|---|---|
| 연금저축 공제 한도 | 연 **600만 원** |
| 연금저축 + IRP 합산 한도 | 연 **900만 원** (IRP만으로 900만 원도 가능) |
| 공제 대상액 | `min( min(연금저축, 600만) + IRP, 900만 )` |
| 공제율 16.5% | 근로소득만 있는 경우 **총급여 5,500만 원 이하**, 그 외 **종합소득금액 4,500만 원 이하** |
| 공제율 13.2% | 위 기준 **초과** |

- 공제율은 지방소득세(10%)를 포함한 값이다: 15% × 1.1 = 16.5%, 12% × 1.1 = 13.2%.
- **경계는 "이하"**: 총급여가 정확히 **55,000,000원이면 16.5%**, 55,000,001원부터 13.2%. 종합소득금액도 정확히 45,000,000원이면 16.5%.

> 참고(블로그 글 불일치, 이번 범위 밖): `posts/2026-pension-savings-fund-guide.md` 19행은 "연금저축만으로 900만 원 전액을 채우는 것도 가능"이라고 되어 있다. 이 앱과 IRP 글(`2026-irp-tax-deduction-guide.md` 19행)은 "연금저축 단독 600만 원까지만 공제"를 기준으로 한다. 글 수정 여부는 사용자에게 따로 확인한다.

## 3. 기능 목록

### MVP (이번에 만들 것)

| 구분 | 내용 |
|---|---|
| 소득 유형 | 세그먼트 버튼: **근로소득자(총급여)** / **그 외(종합소득금액)**. 바꾸면 소득 칸 라벨과 기준 안내("5,500만 원 이하면 16.5%" ↔ "4,500만 원 이하면 16.5%")만 바뀌고 입력값은 유지 |
| 입력 | 소득 금액(원), 연금저축 연 납입액(원), IRP 연 납입액(원). 세 칸 모두 천 단위 쉼표 자동 + 한글 보조 표시 |
| 월 환산 | 납입액 칸 아래 한글 보조 표시 옆에 **월 환산** 표시. 예: `600만 원 · 월 50만 원`, 12로 나누어떨어지지 않으면 `월 약 102,881원` |
| 빠른 입력 | 연금저축: `+50만` `+100만` `600만 채우기` / IRP: `+50만` `+100만` `남은 한도 채우기` (= 900만 − min(연금저축, 600만), 0이면 IRP는 0으로 둠) |
| 결과 | 적용 공제율, 공제 대상 금액, 한도 초과로 공제 안 되는 금액, **예상 환급(세액공제)액**(가장 크게 강조) |
| 추가 안내 | **"한도까지 더 넣으면"** 상자: 남은 한도(월 환산 포함), 추가 환급 가능액, 연금저축으로 더 넣을 수 있는 금액. 한도를 다 채웠으면 "🎉 올해 공제 한도를 모두 채웠어요" |
| 초과 안내 | 초과액이 있으면 이유를 한 줄로: "연금저축은 600만 원까지만 공제돼요" 또는 "두 계좌 합산 900만 원을 넘었어요" |
| 계산 시점 | 입력할 때마다 자동 계산 (`input` 이벤트), 계산 버튼 없음 |
| 잘못된 입력 | 소득 빈칸·0원 → 결과 대신 안내 문구. 납입액 빈칸은 **0원으로 취급**(한 계좌만 쓰는 사람이 많기 때문) |
| 안내 | 사용법 안내 + 면책 문구 (5·6장) |
| 테마 | 블로그 라이트/다크 모드를 그대로 따름 |

### 결정세액 한도 처리 → **MVP는 안내 문구로만**

- 세액공제는 낼 세금(결정세액)보다 많이 돌려받을 수 없다. 하지만 결정세액을 구하려면 근로소득공제, 인적공제, 카드·보험·의료비 공제 등 입력이 많이 필요해 "1분 안에 끝나는 계산기"라는 목적과 맞지 않는다.
- 그래서 결과는 "**한도 안에서 최대로 받을 수 있는 금액**"으로 보여 주고, 결과 아래에 다음 문구를 항상 표시한다:
  > ⓘ 세액공제는 내야 할 세금(결정세액)을 넘어 돌려받을 수 없어요. 소득이 낮거나 다른 공제가 많으면 실제 환급액이 이보다 적을 수 있어요.
- 결정세액 직접 입력은 "나중에 할 것"으로 둔다.

### 나중에 할 것 (MVP 제외)

- 결정세액(또는 작년 원천징수영수증 금액) 입력 → 실제 환급 상한 반영
- 공제받지 못한 초과 납입액의 다음 해 납입분 전환 안내
- ISA 만기 자금 연금계좌 이전 시 추가 공제(이전 금액의 10%, 최대 300만 원)
- 연금계좌 연 납입 한도(합산 1,800만 원) 초과 경고
- 연말까지 남은 달 수 기준 "월 얼마씩 넣으면 되는지" 계산
- 결과 링크 공유(URL 파라미터)

## 4. 계산 공식

### 기호

| 기호 | 뜻 |
|---|---|
| `I` | 소득 금액 (총급여 또는 종합소득금액), 원 |
| `P` | 연금저축 연 납입액, 원 |
| `R` | IRP 연 납입액, 원 |
| `code` | 공제율 코드: 16.5% → `165`, 13.2% → `132` |

### 단계 (구현 시 반드시 이 순서)

1. **공제율 코드**: 근로소득자면 `I ≤ 55,000,000`, 그 외면 `I ≤ 45,000,000` → `165`, 아니면 `132`
2. **연금저축 인정액** `pe = min(P, 6,000,000)`
3. **공제 대상 금액** `eligible = min(pe + R, 9,000,000)`
4. **공제 안 되는 금액** `excess = P + R − eligible`
5. **예상 환급액** `refund = Math.round(eligible × code / 1000)` → 원 단위 반올림
   - 소수(`0.165`)를 곱하지 않고 정수 코드로 계산해 부동소수점 오차를 피한다(첫 앱과 같은 방식).
6. **남은 한도** `remaining = 9,000,000 − eligible`
7. **최대 환급액** `maxRefund = Math.round(9,000,000 × code / 1000)` (1,485,000 또는 1,188,000)
8. **추가 환급 가능액** `extraRefund = maxRefund − refund` (반올림을 따로 하지 않아 `refund + extraRefund = maxRefund`가 항상 성립)
9. **연금저축으로 더 넣을 수 있는 금액** `pensionRoom = min(remaining, 6,000,000 − pe)` (IRP는 `remaining` 전부 가능)
10. **월 환산** `toMonthly(v) = Math.round(v / 12)`, `v % 12 === 0`이 아니면 앞에 "약"을 붙인다.
11. 화면 표시는 `toLocaleString('ko-KR')` + "원", 공제율은 `"16.5%"`/`"13.2%"` 문자열(코드 ÷ 10).

> 참고: 실제 연말정산은 세액공제(12%/15%)와 지방소득세(10%)를 따로 계산하고 원 단위 미만을 버리므로 몇 원 차이가 날 수 있다. 면책 문구로 안내한다.

### 검산 예시 (Review 단계에서 이 값과 정확히 일치해야 함)

모두 `node`로 직접 계산해 확인한 값이다. (단위: 원)

| # | 조건 | 공제율 | 공제 대상 | 초과 | **환급액** | 남은 한도 | 추가 환급 | 연금저축 여유 |
|---|---|---|---|---|---|---|---|---|
| 1 | 근로 5,000만 / 연금저축 600만 / IRP 300만 | 16.5% | 9,000,000 | 0 | **1,485,000** | 0 | 0 | 0 |
| 2 | 근로 8,000만 / 연금저축 800만 / IRP 0 | 13.2% | 6,000,000 | 2,000,000 | **792,000** | 3,000,000 | 396,000 | 0 |
| 3 | 근로 **5,500만(경계)** / 연금저축 400만 / IRP 700만 | 16.5% | 9,000,000 | 2,000,000 | **1,485,000** | 0 | 0 | 0 |
| 4 | 근로 5,000만 / 0 / 0 | 16.5% | 0 | 0 | **0** | 9,000,000 | 1,485,000 | 6,000,000 |
| 5 | 근로 **55,000,001** / 600만 / 300만 | 13.2% | 9,000,000 | 0 | **1,188,000** | 0 | 0 | 0 |
| 6 | 그 외 **4,500만(경계)** / 300만 / 0 | 16.5% | 3,000,000 | 0 | **495,000** | 6,000,000 | 990,000 | 3,000,000 |
| 7 | 그 외 **45,000,001** / 0 / IRP 1,000만 | 13.2% | 9,000,000 | 1,000,000 | **1,188,000** | 0 | 0 | 0 |
| 8 | 근로 6,000만 / 300만 / 0 | 13.2% | 3,000,000 | 0 | **396,000** | 6,000,000 | 792,000 | 3,000,000 |
| 9 | 근로 4,000만 / **1,234,567** / 0 (반올림) | 16.5% | 1,234,567 | 0 | **203,704** | 7,765,433 | 1,281,296 | 4,765,433 |
| 10 | 근로 7,000만 / **1,234,567** / 0 (반올림) | 13.2% | 1,234,567 | 0 | **162,963** | 7,765,433 | 1,025,037 | 4,765,433 |

손 계산 과정:

- **1**: min(600만, 600만) + 300만 = 900만 → 9,000,000 × 165/1000 = 1,485,000. (블로그 IRP 글의 "최대 148만 5천 원"과 일치)
- **2**: 연금저축 800만 중 600만만 인정 → 6,000,000 × 132/1000 = 792,000. 초과 200만 원("연금저축은 600만 원까지만 공제돼요"). IRP로 300만 원 더 넣으면 1,188,000 − 792,000 = 396,000원 더.
- **3**: 400만 + 700만 = 1,100만 → 900만으로 제한, 초과 200만("합산 900만 원 초과"). 5,500만은 "이하"라 16.5% → 1,485,000.
- **4**: 공제 대상 0 → 0원. 남은 한도 900만(월 75만 원), 다 채우면 1,485,000원.
- **5**: 1원 차이로 13.2% → 9,000,000 × 132/1000 = 1,188,000. (블로그 "118만 8천 원"과 일치)
- **6**: 3,000,000 × 165/1000 = 495,000. 남은 600만 중 연금저축으로는 300만까지(600만 − 300만).
- **7**: IRP 단독 1,000만 → 900만 인정, 초과 100만.
- **8**: 3,000,000 × 132/1000 = 396,000.
- **9**: 1,234,567 × 0.165 = 203,703.555 → **203,704**. 추가 환급 = 1,485,000 − 203,704 = 1,281,296.
- **10**: 1,234,567 × 0.132 = 162,962.844 → **162,963**. 추가 환급 = 1,188,000 − 162,963 = 1,025,037.

월 환산 확인: 600만 → 월 500,000 / 900만 → 월 750,000 / 300만 → 월 250,000 / 1,234,567 → 월 약 102,881 / 1,000만 → 월 약 833,333

## 5. 사용법 안내 문구 (화면에 그대로 넣을 초안)

> **이렇게 사용하세요**
> 1. 소득 유형을 고르고 금액을 입력하세요. 직장인은 원천징수영수증의 **총급여**(비과세 제외 연봉), 사업·기타 소득이 있으면 **종합소득금액**을 넣습니다.
> 2. 올해 **연금저축**과 **IRP**에 넣었거나 넣을 **1년 치 금액**을 입력하세요. 없는 계좌는 비워 두면 됩니다.
> 3. **예상 환급액**이 연말정산 때 돌려받는 세금입니다.
> 4. 아래 **"한도까지 더 넣으면"**에서 연말까지 얼마를 더 넣으면 얼마를 더 받는지 확인하세요.
>
> **알아두면 좋아요**
> - 연금저축은 **600만 원**까지, 연금저축 + IRP 합쳐 **900만 원**까지 공제돼요.
> - 총급여 **5,500만 원 이하**(종합소득금액 4,500만 원 이하)면 **16.5%**, 넘으면 **13.2%**를 돌려받아요.
> - 연금저축을 600만 원 넘게 넣었다면 나머지는 **IRP**로 채워야 900만 원 한도를 다 쓸 수 있어요.

위치: 입력 폼 위 접이식(`<details open>`), 첫 앱과 동일.

- "블로그로 돌아가기"는 첫 앱 Review에서 수용된 **`../../`** 상대 경로 사용.

## 8. 파일 구조

```
apps/pension-tax-calculator/
├── spec.md       ← 이 계획서
├── index.html    ← 화면 구조, 사용법·면책 문구, 테마 초기화 인라인 스크립트
├── style.css     ← 앱 전용 스타일 (pt- 접두사, 색은 블로그 CSS 변수)
├── app.js        ← 계산 순수 함수 + 입력 처리·결과 표시
└── icon.svg      ← 앱 아이콘 (apps.json의 icon)
```

- **외부 라이브러리·CDN 없음**. 순수 HTML/CSS/JS.
- `app.js` 구조는 첫 앱과 동일:
  - 상단 `PT_LIMITS` 상수(`pensionLimit: 6000000`, `totalLimit: 9000000`, `salaryThreshold: 55000000`, `globalThreshold: 45000000`, `amountMaxDigits: 12`).
  - 순수 함수 `calculate({incomeType, income, pension, irp})` — `incomeType`: `'salary'|'global'`.
    - 성공: `{ok:true, rateCode, rateLabel, pensionEligible, eligible, excess, excessReason, refund, remaining, extraRefund, maxRefund, pensionRoom}`
      - `excessReason`: `'none'` / `'pension'`(P > 600만이고 합산은 900만 이하) / `'total'`(합산 900만 초과)
    - 실패: `{ok:false, field, message}` — 소득 빈칸·0·정수 아님 → `'소득 금액을 1원 이상 입력해 주세요.'`, 음수·정수 아닌 납입액 → `'납입액은 0원 이상으로 입력해 주세요.'`, 9,999억 초과 → `'금액은 9,999억 원 이하로 입력해 주세요.'`
    - 빈 납입액(`''`, `null`, `undefined`)은 0으로 처리.
  - 보조 순수 함수 `toMonthly(v)` → `{value: Math.round(v/12), approx: v % 12 !== 0}`.
  - 파일 끝: `if (typeof module !== 'undefined') module.exports = { calculate, toMonthly };`
  - 화면 코드 IIFE는 `typeof document === 'undefined'`면 실행하지 않음.
- **금액 입력 처리(첫 앱 그대로, 세 칸에 공통 적용)**:
  - `digitsOnly`, `withCommas`, `koreanAmount`, 커서 위치 유지 `formatAmountInput(el)`.
  - **쉼표 옆 Backspace/Delete 버그 수정**(`removeDigitNextToDeletedComma`)을 반드시 포함. 첫 앱은 금액 칸이 하나라 `lastAmountValue` 하나였지만, 이 앱은 칸이 셋이므로 **입력칸별로 이전 값을 저장**한다(예: `el.dataset.last` 또는 `Map`). 빠른 입력 버튼으로 값을 바꾼 뒤에도 갱신.
  - `inputmode="numeric"`, 최대 12자리.
- 빌드: `build.js`가 `apps/`를 `dist/apps/`로 복사하므로 별도 작업 없음.

## 10. 색상·테마

첫 앱과 **완전히 같은 방식**.

- `index.html`: `<head>`에 블로그와 같은 테마 초기화 인라인 스크립트 → `../../css/style.css` → `style.css` 순서. 파비콘 `../../favicon.svg`.
- 헤더 토글 버튼 `id="theme-toggle" class="theme-toggle pt-theme-toggle"` + `../../js/theme.js` 재사용 → 앱·블로그 테마 동기화, 저장값 없으면 `prefers-color-scheme` 따름.
- 앱 `style.css`의 색은 블로그 변수만 사용: `--color-bg`, `--color-surface`, `--color-text`, `--color-text-secondary`, `--color-accent`, `--color-accent-hover`, `--color-border`, `--color-tag-bg`, `--color-tag-text`.
  - 예외: 오류 강조 `--pt-color-error: #dc2626` 1개(첫 앱처럼 테두리·아이콘에만, 글씨는 `--color-text`).
  - "한도 초과" 금액 강조도 같은 `--pt-color-error`를 테두리/아이콘에만 쓰고, "더 돌려받아요" 금액은 `--color-accent`.
- 모든 클래스·id는 `pt-` 접두사(예: `.pt-field`, `#pt-income`, `.pt-more-box`). 예외: 블로그 토글 스타일 재사용용 `theme-toggle`.

## 12. 검증 체크리스트 (Review 서브에이전트용)

### 계산 정확도
- [ ] 4장 예시 1~10이 **모든 열에서 원 단위까지** 일치 (`node`로 `require('./app.js').calculate()` 직접 호출 + 화면 확인)
- [ ] 경계: 총급여 55,000,000 → 16.5%, 55,000,001 → 13.2% / 종합소득금액 45,000,000 → 16.5%, 45,000,001 → 13.2%
- [ ] 모든 경우 `refund + extraRefund === maxRefund`, `eligible + remaining === 9,000,000`, `eligible + excess === P + R`
- [ ] `excessReason`: 예시 2 → `'pension'`, 예시 3·7 → `'total'`, 예시 1 → `'none'`
- [ ] `toMonthly`: 600만 → 500,000(약 아님), 1,234,567 → 102,881(약)
- [ ] 최대값(소득·납입액 999,999,999,999) → `NaN`/`Infinity` 없음, 정상 표시

### 입력 처리
- [ ] 세 금액 칸 모두 쉼표 자동 삽입, 커서 위치 유지
- [ ] **세 칸 모두** 쉼표 바로 뒤 Backspace / 바로 앞 Delete가 숫자를 지움 (첫 앱 버그 재발 없음), 빠른 입력 후에도 동일
- [ ] 숫자 외 문자 무시, 12자리 제한
- [ ] 납입액 빈칸 → 0원으로 계산 / 소득 빈칸·0 → 결과 대신 안내 문구 + `aria-invalid`
- [ ] 소득 유형 전환 시 라벨·기준 안내가 바뀌고 즉시 다시 계산(입력값 유지)
- [ ] 빠른 입력: `600만 채우기` → 6,000,000 / 연금저축 800만일 때 IRP `남은 한도 채우기` → 3,000,000 / 연금저축 400만일 때 → 5,000,000
- [ ] 월 환산·한글 보조 표시가 입력과 함께 갱신

- [ ] 사용법 안내, 결정세액 안내(ⓘ), 면책 문구(2026년 세법 기준 명시)가 화면에 있음
- [ ] 한도를 다 채우면 "모두 채웠어요", 초과가 있으면 이유 문구 표시
- [ ] "블로그로 돌아가기" 동작
