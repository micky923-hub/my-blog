## Build 단계의 판단 검토

| 판단 | 평가 |
|---|---|
| (1) `excessReason`은 `min(P,600만)+R > 900만`일 때만 `'total'` | **수용.** spec의 "합산"을 `P+R`로 읽으면 연금저축 800만+IRP 200만(인정 800만, 남은 한도 100만)도 "합산 900만 초과"라고 잘못 안내하게 된다. 빌더 방식이 실제 원인과 맞다. 다만 연금저축 600만 초과와 합산 초과가 **동시에** 일어나면(800만+500만) 연금저축 쪽 이유가 빠져 문구를 보완함(아래 수정 2). |
| (2) 12로 나누어떨어지면 한글 단위, 아니면 "월 약 N원" | **수용.** spec 예시(`월 50만 원` / `월 약 102,881원`)와 정확히 같다. 근사값을 한글 단위로 바꾸면 "약 10만 2,881 원"처럼 길어지므로 합리적. |
| (3) 소득 유형을 라디오 fieldset으로 구현 | **수용.** 겉모습은 spec의 세그먼트 버튼과 같고, `legend`·방향키 이동·포커스 표시가 기본 제공돼 접근성이 더 낫다. |
| (4) "한도까지 더 넣으면" 상자 문구 2종 | **수용.** "연금저축으로는 X원까지, IRP로는 Y원 전액을 넣을 수 있어요." / "연금저축은 600만 원을 이미 채웠어요. 남은 Y원은 IRP로 넣으세요." 두 번째 문구는 `pensionRoom=0 && remaining>0`일 때만 나오고, 이는 연금저축 600만 이상일 때뿐이라 내용이 정확하다. |
| (5) 제목에 icon.svg 대신 🐷 이모지 | **수용.** spec 7장 화면 구성과 첫 앱(💰 제목)과 같은 방식. icon.svg는 블로그 카드용. |

## 발견한 문제와 수정 내역

1. **375px에서 남은 한도 줄바꿈이 어색함** (`app.js`, `style.css`)
   - 증상: "3,000,000원 (월 25만 원)"이 좁은 화면에서 "원)"만 다음 줄로 떨어짐.
   - 수정: 남은 한도 금액과 월 환산을 두 개의 `span`(`createElement` + `textContent`)으로 나누고, 월 환산은 `.pt-more-sub`(블록, 작은 글씨, `--color-text-secondary`)로 금액 아래 줄에 표시.
2. **두 한도를 동시에 넘을 때 이유 문구가 하나만 나옴** (`app.js`)
   - 증상: 연금저축 800만 + IRP 500만 → 초과 400만(연금저축 200만 + 합산 200만)인데 "두 계좌 합산 900만 원을 넘었어요."만 표시.
   - 수정: `excessReason==='total'`이면서 연금저축 입력이 600만 초과면 "연금저축 600만 원 한도와 두 계좌 합산 900만 원 한도를 모두 넘었어요."로 표시. `calculate()` 반환값은 spec 그대로 유지(화면 문구만 변경).

수정 후 Node 검증과 브라우저 테스트를 다시 돌려 모두 통과.

## 남은 개선 제안 (선택사항)

- `aria-live`가 결과 영역 전체에 걸려 있어 키 입력마다 화면낭독기가 결과 전체를 다시 읽을 수 있다. 예상 환급액만 live 영역으로 두는 것을 고려(첫 앱과 같은 구조라 이번에는 유지).
- spec "나중에 할 것"의 결정세액 입력이 추가되면 소득이 낮은 사용자의 과대 추정을 줄일 수 있다.
