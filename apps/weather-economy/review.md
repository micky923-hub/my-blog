## 발견한 문제와 수정

|---|---|---|
| 1 | `weThreeDays`가 오늘 이후 예보가 없으면 지난 날짜 예보를 그대로 썼다. 사이트가 며칠 갱신되지 않으면(Actions 중단 등) 지난주 예보로 "폭염 신호"를 내고, 날씨 카드에서 지난 날짜를 "오늘/내일/모레"로 표시했다(오래됨 경고는 떴지만 내용이 틀림) | `app.js`: 지난 날짜는 쓰지 않음. 오늘 이후 예보가 없으면 날씨 카드에 "예보가 오래돼서 오늘 이후 날씨가 없어요" 표시, 신호 없음. 날짜 라벨은 0~2일 차이일 때만 "오늘/내일/모레". `test.js`에 회귀 테스트 1개 추가(총 53개 통과) |
| 2 | fixtures 834KB가 dist로 공개됨 | 앱이 쓰지 않는 `REH`(습도) 항목과, `TMX`/`TMN`을 뺀 00시·21시 항목을 kma-*.json 8개에서 제거 → **634KB**. 응답 모양(쉼표 문자열·`-`·XML 오류·문자열 강수 범주·baseDate/nx/ny 필드)은 그대로, 테스트 53개 통과·시나리오 신호 결과 동일 |

코드 리뷰에서 그 밖에 확인한 것(문제 없음):
- XSS: `innerHTML`로 들어가는 데이터 문자열(단위·품종·하늘·강수형태·날짜)은 모두 `weEsc`. 숫자는 검증된 number만. 칩 이름·신호 제목은 코드 상수.
- 키 노출: 키는 환경변수에서만 읽고 URL은 출력하지 않음. `mask()`가 원문·`encodeURIComponent`·`URLSearchParams` 인코딩·쿼리·주소를 모두 가림.
- 경계값: KST 자정·연말 회차 넘김 테스트, `weIsRealDate`가 2026-02-30 같은 없는 날짜를 버림(윤년은 `Date` 왕복 비교로 처리), 월말은 `setUTCDate` 사용.
- 실패 처리: 최상위 catch + `unhandledRejection` → 항상 exit 0. 브라우저는 fetch 실패·깨진 JSON·`file://`에서 실패 화면, localStorage 예외 무시.

## 남은 위험·배포 후 확인할 것

1. **첫 수동 실행 로그(spec 3-4)**: 해외 IP(GitHub Actions)에서 data.go.kr·kamis.or.kr 접속 여부, KAMIS https 동작(`cause.code` 로그), 기상청 `fcstValue` 모양, 05시 회차에 오늘 TMN/TMX가 있는지(없으면 화면에 "시간별 기온으로 계산한 값" 표시 — 정상 동작).
2. **KAMIS 품목 확정(부록 B)**: 로그의 `[prices] 배추 [품목명으로 찾음, itemcode …]` 줄로 품종·등급·단위 확인, `≠ 계획` 표시가 있으면 부록 갱신. "품목명 목록" 줄 수로 `p_country_code` 생략 시 전국 평균 1줄인지 확인 — 지역별 여러 줄이면 spec 5-1대로 서울(1101)로 바꾸고 화면 문구도 바꿔야 함.
3. **KAMIS 공표 시각**: 첫 2주 `p_regday 오늘 → 000/001` 로그로 18:20 실행 필요 여부 판단(spec 7-2).
4. 시세 오래됨 경고는 5일 기준이라 추석 같은 긴 연휴에는 정상인데도 ⚠가 뜰 수 있음(spec 기준 그대로 둠).
5. `build.js`가 앱 폴더를 통째로 복사해 `spec.md`·`*-instructions.md`·`tools/`도 공개된다(키 없음, 다른 앱과 같은 방식 — 범위 밖이라 그대로 둠).
6. 이전 배포본 이어붙이기(ⓑ) 특성상 다운로드가 두 번 실패한 채 배포되면 날씨 기록이 끊긴다 — 로그 `⚠ 기록 끊김`을 보면 됨.
