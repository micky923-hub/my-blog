## 1. 앱 개요

- **누가**: 블로그의 대환대출 글(`posts/2026-loan-refinancing-guide.md`)을 읽고 "갈아탈까 말까" 고민하는 사람. 주택담보대출·신용대출 보유자.
- **언제**: 대출 앱(토스·카카오페이 등)에서 더 낮은 금리를 봤을 때, 신용점수가 올랐을 때, 대출받은 지 3년이 다가올 때.
- **왜**: 글의 체크리스트 첫 줄 "중도상환수수료와 절감되는 이자를 비교했는가"를 숫자로 바로 확인하기 위해. "수수료 내고 갈아타도 남는지, 몇 달 뒤부터 이득인지"를 알려 준다.

## 2. 꼭 알아야 할 개념 (쉬운 말)

### 상환 방식 (기존 대출·새 대출 각각 고름)

| 방식 | 쉬운 설명 | 매달 내는 돈 |
|---|---|---|
| **원리금균등** | 원금+이자를 합쳐 **매달 같은 금액** | 처음부터 끝까지 거의 같음 |
| **원금균등** | 원금은 매달 같고, 남은 원금이 줄어 **이자가 점점 줄어듦** | 처음이 가장 크고 점점 작아짐 |
| **만기일시** | **이자만** 내다가 마지막 달에 원금을 한꺼번에 | 매달 이자만, 마지막 달 원금 전액 |

### 중도상환수수료

- 대출을 만기 전에 갚으면 내는 돈. 갈아타기 = 기존 대출을 새 대출로 **전부 갚는 것**이라 대상이 된다.
- 일반 계산식: **상환 원금 × 수수료율 × (남은 부과 기간 ÷ 부과 기간)**. 부과 기간은 보통 **대출일로부터 3년(36개월)**이고, 3년이 지나면 **0원**이다. (금소법상 3년 이내 상환 시에만 부과 가능 — 출처 ②)
- 수수료율은 상품·계약 시점마다 다르다.

| 구분 (5대 시중은행 평균) | 2025.1.13 **이전** 계약 | 2025.1.13 **이후** 계약 | 출처 |
|---|---|---|---|
| 주택담보대출 고정금리 | 약 1.4% | 약 0.65% | ① 금융위 보도자료 요약 |
| 주택담보대출 변동금리 | 약 1.2% | 약 0.65% | ① |
| 신용대출 | 약 0.6~0.8% (지침 예시) | 약 0.1~0.4% | ③ 비교 자료 (**미확인**: 공식 평균 수치) |

- 2025년 1월 13일부터 "실비용 안에서만" 받도록 바뀌었고, **그 전 계약에는 옛 요율이 그대로** 적용된다(출처 ①②). 상호금융(새마을금고·농협 단위조합 등)은 2026년 1월부터 확대 적용됐다는 보도가 있다(**미확인**).
- 그래서 앱은 수수료율·부과 기간·경과 기간을 **사용자가 입력**하게 하고, 은행 앱에서 본 **예상 수수료 금액을 직접 넣는 방법**도 준다(결정, 3장).

### 새 대출 인지세 (부대비용)

대출 약정서에 붙는 세금. 은행과 고객이 **50%씩** 내는 것이 일반적이다(2008년 표준약관 개정 이후 관행 — 출처 ⑤, 상품마다 다를 수 있음).

| 대출 금액 (약정서 기재금액) | 인지세 전체 | **고객 부담(50%)** |
|---|---|---|
| 5천만 원 **이하** | 비과세 | **0원** |
| 5천만 원 초과 ~ 1억 원 이하 | 70,000원 | **35,000원** |
| 1억 원 초과 ~ 10억 원 이하 | 150,000원 | **75,000원** |
| 10억 원 초과 | 350,000원 | **175,000원** |

- 근거: 인지세법 제3조(금융기관과의 금전소비대차 증서 = 부동산 소유권 이전 증서 세액 적용), 제6조(기재금액 5천만 원 이하 비과세). 하나·국민·신한은행 안내 자료도 같은 구간·금액(출처 ④⑤⑥).
- **미확인**: 국가법령정보센터 현행 조문을 직접 열어 보지는 못했다(검색에서 2016년 시행본 + 2026년 소개 자료가 같은 금액). 비과세 기준을 5천만 → 2억 원으로 올리는 개정안이 발의됐다는 보도가 있으나 통과 여부 **미확인**(출처 ⑦).

### 기타 비용 → 입력칸 하나로 처리 (결정)

주담대라면 근저당 설정 관련 국민주택채권 할인 비용, 기존 근저당 말소 비용 등이 생길 수 있지만 지역·금액·은행마다 달라 일반화하기 어렵다(**금액 미확인**). → **"기타 비용" 칸 하나**(기본 0원)로 받는다.

## 3. 기능 목록

### MVP (이번에 만들 것)

| 구분 | 내용 |
|---|---|
| ① 기존 대출 | 남은 원금(잔액), 남은 기간(개월), 금리(연 %), 상환 방식(세그먼트 3개) |
| ② 새 대출 | 금리(연 %), 상환 방식(세그먼트 3개), **기간: 기본 "기존 남은 기간과 같게"** + 체크박스 "새 대출 기간 바꾸기"를 켜면 기간 입력칸이 나타남. 새 대출 금액 = 기존 잔액(고정) |
| ③ 갈아타기 비용 | 중도상환수수료 방식 세그먼트 **[요율로 계산 / 금액 직접 입력]**. 요율: 수수료율(%), 부과 기간(개월, 기본 36), 대출받은 지 지난 기간(개월). 직접: 금액(원). **인지세**(자동, 체크박스 "인지세 포함" 기본 켬), **기타 비용**(원, 기본 0) |
| 기간 빠른 입력 | 남은 기간·새 대출 기간 칩 `1년` `2년` `3년` `5년` `10년` `20년` `30년` (→ 12·24·36·60·120·240·360개월). 값과 같은 칩은 `aria-pressed="true"` |
| 결과 | **판정 문구**(가장 크게), **순절감액**, **손익분기 시점**, 남은 기간 총이자(기존 vs 새), 아끼는 이자, 갈아타기 비용 합계(수수료·인지세·기타 내역), 월 상환액(첫 달 기준) 변화 |
| 추가 안내 | 수수료가 남아 있고 결과가 손해면: "중도상환수수료가 없어지는 N개월 뒤에 다시 계산해 보세요." / 기간을 바꿨으면 기간 안내 / 상환 방식이 다르면 방식 안내 (4장 판정 문구) |
| 계산 시점 | 입력할 때마다 자동 계산, 계산 버튼 없음 |
| 잘못된 입력 | 결과 대신 안내 문구 + 해당 칸 `aria-invalid="true"` (5장) |
| 안내 | 사용법 + 면책 문구 (6·7장) |
| 테마 | 블로그 라이트/다크 그대로 |

### 새 대출 기간을 바꿀 수 있게 한다 (결정)

- 실제로 갈아탈 때 기간을 늘리는 경우가 많아 막지 않는다. 대신 **기본은 "같게"**이고, 바꾸면 결과 아래에 안내를 띄운다.
  - 길게: "새 대출 기간이 N개월 더 길어요. 월 상환액은 줄지만, 이자를 내는 기간이 늘어 **총이자는 늘 수 있어요**."
  - 짧게: "새 대출 기간이 N개월 더 짧아요. 총이자는 줄지만 **월 상환액이 늘어요**."
- 예시 F(4장)가 이 함정을 보여 준다: 월 33만 원 줄지만 총 3,349만 원 손해.

### 나중에 할 것 (MVP 제외)

- 월별 상환 스케줄 표, 누적 절감액 그래프
- 변동금리(금리 변동) 시뮬레이션, 거치 기간
- 새 대출 금액을 잔액과 다르게(증액·일부 상환 후 갈아타기)
- 기간별로 수수료율이 다른 상품(슬라이딩 요율), 일(日) 단위 잔존 기간 계산
- 인지세 금액 직접 수정, DSR·한도 계산, 결과 링크 공유(URL 파라미터)

## 4. 계산 공식

### 기호와 단위 (모두 정수)

| 기호 | 뜻 | 정수화 | 예 |
|---|---|---|---|
| `P` | 갈아탈 금액 = 기존 잔액 = 새 대출 금액 (원) | 그대로 | 200,000,000 |
| `n` / `m` | 기존 남은 기간 / 새 대출 기간 (개월) | 그대로 | 240 |
| `Ro` / `Rn` | 기존 / 새 연 금리 × 100 ("0.01%" 단위) | 문자열 파싱 | 4.5% → 450 |
| `D` | 월 이자 분모 = 100 × 100 × 12 = **120,000** | | |
| `F` | 수수료율 × 100 | 문자열 파싱 | 1.2% → 120 |
| `T` / `e` | 부과 기간 / 경과 기간 (개월) | 그대로 | 36 / 12 |

- **월 이자율 = 연 금리 ÷ 12**. 이번 달 이자 = `divRound(B × R, 120000)` (`B` = 그달 시작 잔액).
- **소수 입력의 정수화**: `parseFloat × 100` 금지. 환전 앱의 `parseFixed(str, 2)`처럼 문자열로 정수부·소수부를 잘라 붙인다(`"3.8"` → 380, `"0.65"` → 65, `"4.15"` → 415). 부동소수 오차(`4.15*100 = 415.00000000000006`) 방지.
- **BigInt 사용**: 원리금균등의 `(1+i)^n`을 정확한 정수 분수로 계산하려고 BigInt를 쓴다(외부 라이브러리 아님). 최종 금액은 `Number()`로 바꿔 표시(최대값에서도 약 10¹¹원 수준이라 안전 정수 범위 안 — 아래 경계 확인).
- `divRound(n, d) = (2n·n + d) / (2n·d)` (0 이상 정수의 원 단위 반올림, 0.5는 올림). 환전 앱과 같은 함수.

### 상환 방식별 스케줄 (k = 1 … n개월, 시작 잔액 `B₀ = P`)

매달 **이자를 원 단위로 반올림해 누적**하고, **마지막 달에 남은 원금을 전부 갚아 잔액을 0으로 맞춘다**(결정).

| 방식 | 이번 달 이자 `I_k` | 이번 달 원금 `p_k` (k < n) | 마지막 달 원금 `p_n` |
|---|---|---|---|
| 원리금균등 | `divRound(B × R, D)` | `A − I_k` | 남은 잔액 전부 |
| 원금균등 | `divRound(B × R, D)` | `floor(P / n)` | 남은 잔액 전부 |
| 만기일시 | `divRound(B × R, D)` (= 매달 같음) | 0 | `P` 전부 |

- 원리금균등 월 상환액 `A = floor( P × R × (D+R)ⁿ ÷ ( D × ((D+R)ⁿ − Dⁿ) ) )` — 보통 공식 `P·i·(1+i)ⁿ / ((1+i)ⁿ − 1)`(i = R/D)을 정수 분수로 쓴 것. **원 미만 절사(floor)**. `R = 0`이면 `A = floor(P / n)`.
  - 절사로 정한 이유: 반올림하면 금리 20%·400개월 이상처럼 극단적인 경우 매달 0.5원 오차가 불어나 **마지막 달 상환액이 음수**가 되는 것을 확인했다(잔액 100만 원, 393개월, 19.99% → −58원). 절사는 잔액이 항상 정확한 값 이상이라 음수가 생기지 않는다(마지막 달이 몇백 원 커질 뿐).
  - 원금균등도 같은 이유로 `floor`.
- 월 상환액 = `p_k + I_k`. **첫 달 상환액** = `p_1 + I_1` (만기일시는 이자만, n = 1이면 원금 포함).
- **총이자** = `Σ I_k`. 실제 은행 계산(일할 계산, 10원 단위 처리 등)과 몇 원~몇십 원 다를 수 있다 → 면책 문구로 안내.

### 갈아타기 비용

1. **중도상환수수료**
   - 요율 방식: `e ≥ T`면 **0**, 아니면 `fee = divRound(P × F × (T − e), 10000 × T)`.
   - 직접 입력: 입력한 금액 그대로.
   - 원 미만은 반올림(결정). 실제 은행은 절사하는 곳도 있을 수 있음(**미확인**, 1원 이내 차이).
2. **인지세(고객 부담)**: `P ≤ 5천만` → 0 / `≤ 1억` → 35,000 / `≤ 10억` → 75,000 / 그 초과 → 175,000. "인지세 포함" 체크를 끄면 0.
3. **기타 비용**: 입력값(기본 0).
4. **비용 합계** `cost = fee + stamp + other`.

### 비교 결과

| 항목 | 공식 |
|---|---|
| 기존 총이자 `oldInt` | 기존 대출을 그대로 둘 때 남은 n개월 이자 합 |
| 새 총이자 `newInt` | 새 대출 m개월 이자 합 |
| 아끼는 이자 | `oldInt − newInt` (음수면 "더 내는 이자") |
| **순절감액** `net` | `oldInt − newInt − cost` |
| 월 상환액 변화 | `새 첫 달 − 기존 첫 달` (음수 = 줄어듦) |
| **판정** | `net > 0` 유리 / `net < 0` 불리 / `net = 0` 차이 없음 |

### 손익분기 시점

- `S_k` = 1~k개월 동안 **(기존 이자 − 새 이자)의 누적합**. 기간이 끝난 쪽은 그 뒤 이자 0으로 본다. k는 1 … `max(n, m)`.
- **손익분기 = "누적 절감 이자가 비용 이상인 상태가 끝까지 유지되는 첫 달"**: `S_j ≥ cost`가 모든 `j ≥ k`에서 성립하는 가장 작은 k. 구현은 끝에서부터 거꾸로 훑는다.
  - 이렇게 정한 이유: 기간을 늘리면 앞에서는 이득이다가 기존 대출이 끝난 뒤 새 이자만 쌓여 다시 손해가 될 수 있다. "처음 넘은 달"로 하면 오해를 준다.
- `net ≤ 0`이면 손익분기 **없음** ("기간 전체로 보면 갈아타는 비용을 되찾지 못해요").
- 표시: `15개월째부터 이득 (약 1년 3개월)`. 12개월 미만은 "N개월째부터 이득".

### 판정 문구 (결과 맨 위)

| 경우 | 문구 |
|---|---|
| 유리 | "**갈아타는 게 유리해요.** 비용을 빼고도 약 {net}원 아껴요." |
| 불리 | "**지금 갈아타면 손해예요.** 비용이 아끼는 이자보다 {−net}원 많아요." |
| 같음 | "갈아타도 차이가 없어요." |
| (불리 + 요율 방식 + e < T) 추가 | "중도상환수수료가 없어지는 {T − e}개월 뒤에 다시 계산해 보세요." |
| (m ≠ n) 추가 | 3장 "기간 안내" 문구 |
| (상환 방식이 다름) 추가 | "기존과 새 대출의 상환 방식이 달라요. 이자 차이에는 금리뿐 아니라 **원금을 갚는 속도 차이**도 섞여 있어요." |

## 6. 사용법 안내 문구 (화면에 그대로 넣을 초안)

> **이렇게 사용하세요**
> 1. **기존 대출**의 남은 원금, 남은 기간, 금리, 상환 방식을 넣으세요. 대출 앱이나 은행 앱의 "대출 상세"에 나와 있어요.
> 2. **새 대출**의 금리와 상환 방식을 고르세요. 기간은 기본으로 기존 남은 기간과 같게 계산해요.
> 3. **중도상환수수료**는 수수료율과 대출받은 지 지난 기간을 넣으면 자동으로 계산해요. 은행 앱에서 예상 수수료 금액을 봤다면 "금액 직접 입력"을 고르세요.
> 4. 맨 아래에서 **갈아타는 게 유리한지**, 비용을 빼고 **얼마를 아끼는지**, **몇 개월째부터 이득인지** 확인하세요.
>
> **알아두면 좋아요**
> - **원리금균등**은 매달 같은 금액, **원금균등**은 처음에 많이 내고 점점 줄어요. **만기일시**는 이자만 내다가 마지막에 원금을 갚아요.
> - 중도상환수수료는 보통 **대출받은 지 3년**이 지나면 없어져요. 3년이 거의 다 됐다면 기다렸다 갈아타는 게 나을 수 있어요.
> - 새 대출 기간을 늘리면 **월 부담은 줄어도 총이자는 늘 수 있어요.**
> - 새 대출이 5천만 원을 넘으면 **인지세**를 은행과 절반씩 내요(고객 3만 5천~17만 5천 원).

## 9. 파일 구조

```
apps/loan-refinance-calculator/
├── spec.md       ← 이 계획서
├── index.html    ← 화면 구조, 사용법·면책 문구, 테마 초기화 인라인 스크립트
├── style.css     ← 앱 전용 스타일 (lr- 접두사, 색은 블로그 CSS 변수)
├── app.js        ← 계산 순수 함수 + 입력 처리·결과 표시
└── icon.svg      ← 앱 아이콘 (apps.json의 icon)
```

- **외부 라이브러리·CDN·네트워크 요청 없음**. 순수 HTML/CSS/JS.
- `app.js` 구조는 앞의 앱과 동일:
  - 상단 상수 `LR_LIMITS`(`balanceMin: 1000000`, `balanceMaxDigits: 10`, `monthsMax: 600`, `rateMax: '20'`, `feeRateMax: '5'`, `feePeriodMax: 60`, `amountMaxDigits: 9`), `LR_STAMP`(구간표 배열), `LR_TYPES`(`annuity`/`equal`/`bullet` → 한글 이름).
  - 순수 함수 `calculate(p)` — 입력 `{balance, remainMonths, oldRate, oldType, newRate, newType, termChange, newMonths, feeMode, feeRate, feePeriod, elapsed, feeAmount, includeStamp, otherCost}`. 숫자는 **문자열·숫자 모두** 받음(쉼표 허용).
    - 성공: `{ok:true, oldFirst, newFirst, firstDiff, oldLast, newLast, oldInterest, newInterest, interestSaved, prepayFee, feeWaived, stampTax, otherCost, totalCost, net, verdict:'gain'|'loss'|'even', breakevenMonth (number|null), monthsUntilFeeFree (number|null), termDiff, typeChanged}` (금액은 Number)
    - 실패: `{ok:false, field, message}` — 메시지는 5장 문구.
  - 보조 순수 함수: `parseFixed(str, decimals)` → BigInt|null, `divRound(n, d)`, `schedule(P, R, months, type)` → `{interests[], payments[], totalInterest, firstPayment, lastPayment}`(BigInt), `stampTax(P)`, `breakeven(oldInts, newInts, cost)`.
  - 파일 끝: `if (typeof module !== 'undefined') module.exports = { calculate, parseFixed, divRound, schedule, stampTax, breakeven };`
  - 화면 코드 IIFE는 `typeof document === 'undefined'`면 실행하지 않음.
- 결과 표시는 `textContent`/`createElement`만(`innerHTML`에 사용자 입력 금지).
- 빌드: `build.js`가 `apps/`를 `dist/apps/`로 복사하므로 별도 작업 없음.

## 11. 색상·테마

앞의 세 앱과 **완전히 같은 방식**.

- `index.html` `<head>`: 블로그와 같은 테마 초기화 인라인 스크립트 → `../../css/style.css` → `style.css` 순서. 파비콘 `../../favicon.svg`.
- 헤더 토글 `id="theme-toggle" class="theme-toggle lr-theme-toggle"` + `../../js/theme.js` 재사용 → 앱·블로그 테마 동기화, 저장값 없으면 `prefers-color-scheme`.
- 앱 `style.css`의 색은 블로그 변수만: `--color-bg`, `--color-surface`, `--color-text`, `--color-text-secondary`, `--color-accent`, `--color-accent-hover`, `--color-border`, `--color-tag-bg`, `--color-tag-text`.
  - 예외: `--lr-color-error: #dc2626` 1개(오류·손해 판정의 테두리·아이콘에만, 글씨는 `--color-text`).
  - 유리 판정·순절감액은 `--color-accent`. 주황색은 **아이콘에만** 쓰고 화면 UI에는 쓰지 않는다.
- 모든 클래스·id는 `lr-` 접두사(예: `.lr-section`, `#lr-balance`, `.lr-chip`). 예외: `theme-toggle`, `main-content`(앞 앱과 동일).

## 13. 검증 체크리스트 (Review 서브에이전트용)

### 계산 정확도
- [ ] 4장 예시 A~G가 **모든 열(첫 달·마지막 달·총이자·수수료·인지세·비용·순절감액·손익분기)에서 원 단위까지** 일치 (`node`로 `require('./app.js').calculate()` 직접 호출 + 화면 확인)
- [ ] 판정 문구·추가 안내가 예시별로 맞게 나옴(E 수수료 30개월 안내, F 기간 안내, G 방식 안내)
- [ ] 독립 구현(부동소수점 등)과 무작위 입력 비교 시 차이 0원
- [ ] 불변식: 각 스케줄의 원금 합 = P, 모든 달 상환액 ≥ 0, `net = oldInterest − newInterest − totalCost`, `totalCost = prepayFee + stampTax + otherCost`
- [ ] 손익분기: `net ≤ 0`이면 null, 그 외에는 k 이후 모든 달 누적 절감 ≥ 비용이고 k−1에서는 아님(k > 1일 때)
- [ ] 소수 입력 정밀도: `4.15`, `0.65`, `3.8`이 문자열 파싱으로 정확히 정수화
- [ ] 4장 경계 표 전부(인지세 경계 5개, 금리 0%, 1개월, 경과 = 부과 기간, 동일 조건, 극단·최대값) → `NaN`/`Infinity`/음수 상환액 없음

### 입력 처리
- [ ] 금액 3칸 쉼표 자동, 커서 위치 유지, **쉼표 옆 Backspace/Delete가 숫자를 지움**(칩·빠른 입력 후에도)
- [ ] 금리·수수료율 소수점 1개, 둘째 자리까지, 문자 무시
- [ ] 잘못된 입력(빈칸·범위 초과·소수 기간) → 결과 대신 5장 문구 + `aria-invalid`, 고치면 복구
- [ ] 수수료 방식 전환 시 칸 표시/숨김·검사 대상 전환, 값 유지
- [ ] "새 대출 기간 바꾸기" 켜기/끄기, 끄면 m = n, 기간 칩 눌림 상태
- [ ] 인지세 체크 해제 → 비용에서 빠짐, 잔액 바꾸면 인지세 힌트 갱신

### 화면·접근성
- [ ] 375/320px 가로 스크롤 없음(최대값 포함), 1280px 정상, 3칸 세그먼트 줄바꿈 없음
- [ ] 터치 영역 44px, 입력 글자 16px 이상, 모든 입력에 `<label>`/`legend`, 결과 `aria-live="polite"`
- [ ] 사용법 안내(6장)와 면책 문구(7장: DSR·한도·변동금리·계약 시점) 존재
- [ ] 손해 판정은 테두리만 빨강, 글씨는 테마 색
- [ ] "블로그로 돌아가기" 동작

### 테마·아이콘
- [ ] 블로그↔앱 다크 모드 동기화, 저장값 없을 때 시스템 설정 따름
- [ ] `style.css`에 hex 색 없음(`--lr-color-error` 1개 제외)
- [ ] `icon.svg` 단독으로 열림, 88px에서 집·하락 화살표·% 식별, 기존 파랑·초록·보라 아이콘과 구분

### 구조·범위
- [ ] 파일은 `apps/loan-refinance-calculator/` 안에만, 블로그 다른 파일 변경 없음
- [ ] 외부 라이브러리·CDN·네트워크 요청 없음, 콘솔 에러 없음, `innerHTML`에 사용자 입력 없음
- [ ] `npm run build` 후 `dist/apps/loan-refinance-calculator/`에서 CSS·JS·아이콘 경로 정상
