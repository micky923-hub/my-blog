# 환전 수수료 계산기 (우대율 반영) — 계획서 (spec)

> 상태: **승인됨 (2026-10-08)** · 작성일 2026-10-08
> 위치: `apps/exchange-fee-calculator/` · 블로그: financialdiary.co.kr
> 앞의 두 앱(`savings-calculator`, `pension-tax-calculator`)의 구조·사용감을 그대로 따른다. CSS 접두사는 **`fx-`**.

## 1. 앱 개요

- **누가**: 블로그의 달러 투자 글(`posts/2026-dollar-investment-guide.md`)을 읽은 재테크 입문자, 해외여행을 앞둔 사람.
- **언제**: 여행 전 엔화·유로를 바꿀 때, 달러예금을 처음 시작할 때, 갖고 있던 외화를 원화로 다시 바꿀 때.
- **왜**: "1만 달러 바꾸면 수수료가 얼마지?", "우대 90% 쿠폰이면 얼마나 아끼지?"를 은행 앱 숫자만 넣고 바로 확인하기 위해.

## 2. 환전 수수료, 쉽게 이해하기

| 용어 | 쉬운 설명 |
|---|---|
| **매매기준율** | 은행이 정하는 "수수료 없는 기준 가격". 은행 앱 환율 화면에 나온다. |
| **환전 스프레드(수수료율)** | 기준 가격에 얹는 비율. 은행이 이걸로 돈을 번다. 현찰 기준 예시: USD·JPY 약 **1.75%**, EUR 약 **1.99%**, CNY 약 **5%**. 은행·현찰/송금마다 다르다. |
| **우대율** | 스프레드에서 깎아 주는 비율. 90% 우대 = 스프레드의 10%만 낸다. |
| **실제 수수료율** | `스프레드 × (1 − 우대율)` 예: 1.75% × (1 − 0.9) = 0.175% |
| **살 때** (원화 → 외화) | 적용 환율 = 매매기준율 × (1 + 실제 수수료율) → 기준보다 **비싸게** 산다 |
| **팔 때** (외화 → 원화) | 적용 환율 = 매매기준율 × (1 − 실제 수수료율) → 기준보다 **싸게** 판다 |

### 실시간 환율 API는 쓰지 않는다 (결정)

- **이유**: ① 외부 서비스에 의존하게 되고, ② 대부분 API 키가 필요해 정적 블로그에 키를 노출하게 되며, ③ 네트워크가 실패하면 계산기 자체가 멈춘다. ④ 은행마다 매매기준율이 조금씩 달라 "내 은행 숫자"를 넣는 편이 더 정확하다.
- **대신**: 매매기준율은 사용자가 입력한다. 입력칸 아래에 "은행 앱의 오늘 **매매기준율**을 넣어 주세요"라고 안내한다. 첫 화면에는 예시 환율이 채워져 있고 "예시 환율"이라고 표시한다.
- 스프레드도 은행마다 다르므로 **사용자가 바꿀 수 있는 입력값**으로 두고, 통화를 고르면 기본값만 자동으로 채운다.

## 3. 기능 목록

### MVP (이번에 만들 것)

| 구분 | 내용 |
|---|---|
| 통화 선택 | 세그먼트 버튼(라디오 fieldset): **USD 🇺🇸 / JPY 🇯🇵 / EUR 🇪🇺 / CNY 🇨🇳**. 바꾸면 스프레드 기본값과 예시 매매기준율이 자동으로 채워지고, 금액 단위(달러/엔/유로/위안)와 환율 라벨이 바뀐다. 외화 금액·우대율은 유지 |
| 방향 선택 | 세그먼트 버튼: **살 때 (원화 → 외화)** / **팔 때 (외화 → 원화)** |

| 잘못된 입력 | 결과 대신 안내 문구 + 해당 칸 `aria-invalid="true"` (5장 오류 문구) |
| 안내 | 사용법 안내 + 면책 문구 (6·7장) |
| 테마 | 블로그 라이트/다크 모드 그대로 따름 |

### 나중에 할 것 (MVP 제외)

- 원화 금액을 넣으면 살 수 있는 외화를 계산하는 "역계산" 모드
- 외화 소수 금액(센트 단위) 입력
- 현찰 / 송금(전신환) 구분 스프레드 프리셋, 통화 추가(GBP, AUD, VND 등)
- 은행별 스프레드 프리셋, 여러 번 나눠 환전(분할 환전) 시뮬레이션
- 실시간 환율 API 연동, 결과 링크 공유(URL 파라미터)

## 4. 계산 공식

### 기호

| 기호 | 뜻 | 예 |
|---|---|---|
| `A` | 외화 금액 (정수, 엔은 실제 엔) | 10,000 |
| `U` | 환율 단위: JPY는 **100**, 나머지는 1 | |
| `R100` | 매매기준율 × 100 (정수, "원의 1/100") | 1,300.00 → 130000 |
| `S` | 스프레드 × 100 (정수, "0.01%" 단위) | 1.75% → 175 |
| `p` | 우대율 (정수 %) | 90 |
| `E` | 실제 수수료율, 백만분율 정수 `= S × (100 − p)` | 175 × 10 = 1750 → 0.175% |
| `S6` | 우대 없는 수수료율, 백만분율 `= S × 100` | 17500 → 1.75% |

### 단계 (구현 시 반드시 이 순서)

1. **입력을 정수로 변환** — 소수 입력(`1,512.34`, `1.99`)은 `parseFloat × 100`이 아니라 **문자열로** 정수부·소수부를 잘라 붙인다(`"1512" + "34"` → 151234). 부동소수점 오차(`1.15 * 100` = 114.99999999999999, `0.29 * 100` = 28.999999999999996) 방지.
2. **기준 원화** `base = divRound(A × R100, 100 × U)`
3. **수수료** `fee = divRound(A × R100 × E, 100 × U × 1,000,000)`
4. **필요한/받는 원화** — 살 때 `krw = base + fee`, 팔 때 `krw = base − fee`
5. **우대 없을 때 수수료** `feeNoPref = divRound(A × R100 × S6, 100 × U × 1,000,000)`
6. **아낀 금액** `saved = feeNoPref − fee`
7. **적용 환율(표시용)** — 살 때 `R100 × (1,000,000 + E)`, 팔 때 `R100 × (1,000,000 − E)`를 `1e8`로 나눈 값. 화면에는 **`divRound(분자, 10000n)`으로 정수 반올림해 소수 넷째 자리까지 만든 뒤(부동소수점 `toFixed` 금지) 끝의 0 제거, 최소 둘째 자리** (1302.275 → `1,302.275`, 1300 → `1,300.00`, 1518.3591132 → `1,518.3591`).
8. **실제 수수료율(표시용)** `E / 10,000` % (1750 → `0.175%`, 0 → `0%`).

- `divRound(n, d)`: **BigInt**로 계산하는 원 단위 반올림(0.5는 올림) = `(2n·n + d) / (2n·d)`. `A × R100 × E` 는 최대 약 10²¹이라 일반 Number로는 정밀도가 깨지므로 BigInt를 쓴다(모든 최신 브라우저·Node 지원, 외부 라이브러리 아님). 결과는 `Number()`로 바꿔 표시(최대 약 10¹⁴원이라 안전).
- 수수료를 따로 반올림하고 `krw = base ± fee`로 만들기 때문에 **`krw = base ± fee`가 항상 정확히 성립**한다(화면 숫자끼리 더해도 1원도 안 어긋남).
- 실제 은행은 적용 환율을 소수 둘째 자리에서 끊어 고시하는 경우가 많아 몇 원~몇십 원 차이가 날 수 있다 → 면책 문구로 안내. (적용 환율을 먼저 둘째 자리로 반올림하면 블로그 기준 예시 B의 수수료가 22,800원이 되어 "스프레드 × (1−우대율)" 설명과 어긋나므로, 반올림 전 값을 쓴다.)

### 검산 예시 (Review 단계에서 이 값과 정확히 일치해야 함)

모두 `node -e`로 BigInt 공식과, 별도의 부동소수점 계산 두 가지로 확인한 값이다. (단위: 원)

| # | 조건 | 실제 수수료율 | 적용 환율 | 기준 원화 | 수수료 | **필요/받는 원화** | 우대 없을 때 수수료 | **아낀 금액** |
|---|---|---|---|---|---|---|---|---|
| A | USD **살 때** 10,000달러, 1,300, 1.75%, 우대 0% | 1.75% | 1,322.75 | 13,000,000 | 227,500 | **13,227,500** | 227,500 | **0** |
| B | USD **살 때** 10,000달러, 1,300, 1.75%, 우대 **90%** | 0.175% | 1,302.275 | 13,000,000 | 22,750 | **13,022,750** | 227,500 | **204,750** |
| C | USD **팔 때** 10,000달러, 1,300, 1.75%, 우대 50% | 0.875% | 1,288.625 | 13,000,000 | 113,750 | **12,886,250** | 227,500 | **113,750** |
| D | JPY **살 때** 300,000엔, **100엔당 900**, 1.75%, 우대 70% | 0.525% | 904.725 / 100엔 | 2,700,000 | 14,175 | **2,714,175** | 47,250 | **33,075** |
| E | EUR 살 때 1,234유로, 1,512.34, 1.99%, 우대 80% (반올림) | 0.398% | 1,518.3591 | 1,866,228 | 7,428 | **1,873,656** | 37,138 | **29,710** |
| F | CNY 팔 때 5,000위안, 190.55, 5%, 우대 50% (반올림) | 2.5% | 185.7863 | 952,750 | 23,819 | **928,931** | 47,638 | **23,819** |
| G | USD 살 때 10,000달러, 1,300, 1.75%, 우대 **100%** | 0% | 1,300.00 | 13,000,000 | 0 | **13,000,000** | 227,500 | **227,500** |
| H | JPY 팔 때 **12,345엔**, 100엔당 905.12, 1.75%, 우대 90% (반올림) | 0.175% | 903.536 / 100엔 | 111,737 | 196 | **111,541** | 1,955 | **1,759** |

손 계산 과정:

- **A**: 1,300 × 1.0175 = 1,322.75. 10,000 × 1,322.75 = 13,227,500. 수수료 13,000,000 × 0.0175 = 227,500.
- **B**: 실제 수수료율 1.75% × (1 − 0.9) = 0.175%. 수수료 13,000,000 × 0.00175 = 22,750. 아낀 금액 227,500 − 22,750 = 204,750. 적용 환율 1,300 × 1.00175 = 1,302.275.
- **C**: 1.75% × 0.5 = 0.875%. 1,300 × (1 − 0.00875) = 1,288.625. 받는 원화 13,000,000 − 113,750 = 12,886,250.
- **D**: 300,000엔 = 100엔 × 3,000 → 기준 원화 3,000 × 900 = 2,700,000. 1.75% × 0.3 = 0.525% → 수수료 14,175. 우대 없으면 2,700,000 × 0.0175 = 47,250.
- **E**: 1,234 × 1,512.34 = 1,866,227.56 → **1,866,228**. 수수료 1,866,227.56 × 0.00398 = 7,427.59 → **7,428**. 우대 없으면 × 0.0199 = 37,137.93 → 37,138.
- **F**: 5,000 × 190.55 = 952,750. 수수료 × 0.025 = 23,818.75 → **23,819**. 우대 없으면 47,637.5 → **47,638**(0.5 올림). 아낀 금액 47,638 − 23,819 = 23,819.
- **G**: 우대 100%면 수수료 0, 적용 환율 = 매매기준율.
- **H**: 12,345엔 × 905.12 / 100 = 111,737.064 → 111,737. 수수료 × 0.00175 = 195.54 → 196. 받는 원화 111,737 − 196 = 111,541.

**블로그 달러 글과 맞추기**: 글의 "1,300원일 때 1만 달러(1,300만 원) 환전 시 수수료 13만~22만 원"은 1,300만 원 × 1% = **130,000원** ~ × 1.75% = **227,500원**(예시 A)이다. 글이 권하는 90% 우대를 쓰면 예시 B처럼 22,750원으로 줄어 **204,750원**을 아낀다.

추가 경계 확인용:

| 조건 | 기대 결과 |
|---|---|
| 스프레드 0% | 수수료 0, 아낀 금액 0, 적용 환율 = 매매기준율 |
| 외화 1달러, 1,300, 1.75%, 우대 0%, 살 때 | 수수료 23 (22.75 → 23), 필요 원화 1,323 |
| 최대값: 999,999,999달러, 99,999.99원, 10%, 0% | `NaN`/`Infinity` 없음, 정상 표시 |

## 5. 입력 규칙과 오류 문구

| 칸 | 허용 | 기본값 | 오류 문구 |
|---|---|---|---|
| 외화 금액 | 정수 1 ~ 999,999,999 (9자리), 쉼표 자동 | 10,000 | "외화 금액을 1 이상 입력해 주세요." |
| 매매기준율 | 0.01 ~ 99,999.99, 소수 둘째 자리까지, 정수부 쉼표 자동 | 통화별 예시값 | "매매기준율을 0보다 크게 입력해 주세요. (소수 둘째 자리까지)" |
| 스프레드 | 0 ~ 10, 소수 둘째 자리까지 | 통화별 기본값 | "스프레드는 0~10% 사이로 입력해 주세요." |
| 우대율 | 정수 0 ~ 100 | 90 | "우대율은 0~100% 사이의 정수로 입력해 주세요." |

### 통화별 기본값

| 통화 | 단위 표시 | 환율 기준 | 스프레드 기본값 | 예시 매매기준율 |
|---|---|---|---|---|
| USD | 달러 | 1달러당 | 1.75 | 1,300.00 |
| JPY | 엔 | **100엔당** | 1.75 | 900.00 |
| EUR | 유로 | 1유로당 | 1.99 | 1,500.00 |
| CNY | 위안 | 1위안당 | 5.00 | 190.00 |

- 통화를 바꾸면 스프레드·매매기준율이 **항상** 위 값으로 바뀐다(통화마다 의미가 달라 이전 값을 유지하면 오해 소지). 매매기준율 칸 아래 힌트에 "예시 환율이에요. 은행 앱의 오늘 매매기준율로 바꿔 주세요."를 표시하고, 사용자가 직접 고치면 힌트를 "100엔당 900원" 같은 보조 표시로 바꾼다.
- 첫 화면은 **예시 B**(USD, 살 때, 10,000달러, 1,300, 1.75%, 90%)로 채워 바로 결과가 보이게 한다.

### 입력 처리 (앞의 두 앱 그대로)

- 외화 금액: `digitsOnly`, `withCommas`, 커서 위치 유지 `formatAmountInput(el)`, **쉼표 옆 Backspace/Delete 수정(`removeDigitNextToDeletedComma`)**, 입력칸별 이전 값 저장(`lastValues[el.id]`), 빠른 입력 후에도 갱신. `inputmode="numeric"`.
- 매매기준율: 정수부만 쉼표 처리, 소수점 하나와 소수 둘째 자리까지 허용(`inputmode="decimal"`). 정수부에 같은 쉼표 Backspace/Delete 수정 적용. 소수 셋째 자리 이후 입력은 무시.
- 스프레드·우대율: 쉼표 없음, `inputmode="decimal"` / `"numeric"`.
- 금액 칸 아래 보조 표시: `10,000달러 · 1만 달러`, JPY는 `300,000엔 · 30만 엔`.

## 6. 사용법 안내 문구 (화면에 그대로 넣을 초안)

> **이렇게 사용하세요**
> 1. 바꿀 **통화**와 **살 때(원화 → 외화) / 팔 때(외화 → 원화)**를 고르세요.
> 2. 바꿀 **외화 금액**을 입력하세요. 엔화도 실제 엔 금액(예: 300,000엔)을 넣으면 됩니다.
> 3. 은행 앱 환율 화면에서 오늘의 **매매기준율**을 확인해 넣으세요. **엔화는 100엔당 환율**입니다(예: 900원).
> 4. **스프레드**는 통화별 보통 값이 자동으로 들어가요. 내 은행 수수료율을 알면 바꿔 넣으세요.
> 5. 쿠폰·우대 이벤트의 **우대율**을 고르면, 맨 아래 **아낀 금액**이 바로 바뀝니다.
>
> **알아두면 좋아요**
> - **매매기준율**은 수수료가 붙지 않은 기준 가격이에요.
> - **스프레드**는 은행이 얹는 수수료율이에요. 현찰은 보통 달러·엔 약 1.75%, 유로 약 1.99%, 위안 약 5%예요.
> - **우대율 90%**면 스프레드의 10%만 내요. 1.75% × 0.1 = 0.175%
> - 해외송금·외화예금(전신환)은 현찰보다 스프레드가 낮은 경우가 많아요.

위치: 입력 폼 위 접이식(`<details open>`), 앞의 두 앱과 동일.

## 7. 면책 문구

> ※ 이 계산기는 이해를 돕기 위한 **참고용**입니다. 환율과 환전 수수료(스프레드)는 **은행·지점·시간대마다 다르고**, **현찰과 송금(전신환)의 수수료도 다릅니다**. 실제 은행은 적용 환율을 소수점 아래에서 끊어 계산하므로 몇 원 차이가 날 수 있습니다. 정확한 금액은 환전하려는 은행 앱이나 창구에서 확인하세요.

## 9. 파일 구조

```
apps/exchange-fee-calculator/
├── spec.md       ← 이 계획서
├── index.html    ← 화면 구조, 사용법·면책 문구, 테마 초기화 인라인 스크립트
├── style.css     ← 앱 전용 스타일 (fx- 접두사, 색은 블로그 CSS 변수)
├── app.js        ← 계산 순수 함수 + 입력 처리·결과 표시
└── icon.svg      ← 앱 아이콘 (apps.json의 icon)
```

- **외부 라이브러리·CDN 없음**. 순수 HTML/CSS/JS.
- `app.js` 구조는 앞의 앱과 동일:
  - 상단 `FX_CURRENCIES` 상수: `{ USD:{unit:1, name:'달러', spread:'1.75', sampleRate:'1300.00'}, JPY:{unit:100, name:'엔', …}, EUR:{…}, CNY:{…} }`, `FX_LIMITS` 상수(`amountMaxDigits: 9`, `rateMax: '99999.99'`, `spreadMax: '10'`).
  - 순수 함수 `calculate({currency, direction, amount, rate, spread, preferential})` — `direction`: `'buy'|'sell'`, 숫자 입력은 **문자열 또는 숫자** 모두 받음(쉼표 허용).
    - 성공: `{ok:true, unit, effRatePct, appliedRate, appliedRateText, base, fee, krw, feeNoPref, saved}` (금액은 Number)
    - 실패: `{ok:false, field, message}` — `field`: `'amount'|'rate'|'spread'|'preferential'`, 메시지는 5장 문구.
  - 보조 순수 함수 `parseFixed(str, decimals)` → BigInt 또는 `null`, `divRound(n, d)`, `formatRate(…)`.
  - 파일 끝: `if (typeof module !== 'undefined') module.exports = { calculate, parseFixed, divRound };`
  - 화면 코드 IIFE는 `typeof document === 'undefined'`면 실행하지 않음.
- 결과 표시는 `textContent`/`createElement`만 사용(`innerHTML`에 사용자 입력 금지).
- 빌드: `build.js`가 `apps/`를 `dist/apps/`로 복사하므로 별도 작업 없음.

## 11. 색상·테마

앞의 두 앱과 **완전히 같은 방식**.

- `index.html` `<head>`: 블로그와 같은 테마 초기화 인라인 스크립트 → `../../css/style.css` → `style.css` 순서. 파비콘 `../../favicon.svg`.
- 헤더 토글 `id="theme-toggle" class="theme-toggle fx-theme-toggle"` + `../../js/theme.js` 재사용 → 앱·블로그 테마 동기화, 저장값 없으면 `prefers-color-scheme` 따름.
- 앱 `style.css`의 색은 블로그 변수만: `--color-bg`, `--color-surface`, `--color-text`, `--color-text-secondary`, `--color-accent`, `--color-accent-hover`, `--color-border`, `--color-tag-bg`, `--color-tag-text`.
  - 예외: 오류 강조 `--fx-color-error: #dc2626` 1개(테두리·아이콘에만, 글씨는 `--color-text`).
  - 아낀 금액은 `--color-accent`. 보라색은 **아이콘에만** 쓰고 화면 UI에는 쓰지 않는다(블로그 팔레트 준수).
- 모든 클래스·id는 `fx-` 접두사(예: `.fx-field`, `#fx-amount`, `.fx-chip`). 예외: 블로그 토글 재사용용 `theme-toggle`.

## 13. 검증 체크리스트 (Review 서브에이전트용)

### 계산 정확도
- [ ] 4장 예시 A~H가 **모든 열에서 원 단위까지** 일치 (`node`로 `require('./app.js').calculate()` 직접 호출 + 화면 확인). 적용 환율 표시 문자열도 일치(`1,302.275`, `1,518.3591`, `185.7863`, `1,300.00`)
- [ ] 모든 경우 살 때 `krw === base + fee`, 팔 때 `krw === base − fee`, `saved === feeNoPref − fee`, `saved ≥ 0`
- [ ] JPY는 100엔 기준: 300,000엔 × 100엔당 900 → 기준 원화 2,700,000 (×100 실수 없음)
- [ ] 소수 입력 정밀도: 스프레드 `1.15`, `0.29`, 매매기준율 `1512.34`가 문자열 파싱으로 정확히 정수화됨
- [ ] 경계: 스프레드 0, 우대 0·100, 1달러(수수료 23), 최대값 → `NaN`/`Infinity` 없음
- [ ] 독립 구현(부동소수점)과 무작위 입력 비교 시 차이 0원 (0.5 경계 근처만 BigInt 기준 확인)

### 입력 처리
- [ ] 외화 금액·매매기준율 쉼표 자동, 커서 위치 유지, **쉼표 옆 Backspace/Delete가 숫자를 지움**(빠른 입력 후에도)
- [ ] 매매기준율 소수점 1개, 소수 둘째 자리까지만, 숫자 외 문자 무시
- [ ] 잘못된 입력(빈칸·0·범위 초과·우대율 소수) → 결과 대신 5장 문구 + `aria-invalid`, 고치면 복구
- [ ] 통화 전환 → 스프레드·예시 환율·단위·라벨("100엔당") 변경, 금액·우대율 유지, 즉시 재계산
- [ ] 방향 전환 → "필요한 원화" ↔ "받는 원화", 적용 환율 위/아래 바뀜
- [ ] 우대율 칩 → 값 입력 + 눌림 상태 표시, 직접 입력한 값과 같으면 해당 칩 눌림

### 화면·접근성
- [ ] 375px 가로 스크롤 없음(최대값 포함), 1280px 정상, 통화 세그먼트 줄바꿈 정상
- [ ] 터치 영역 44px, 입력 글자 16px 이상, 모든 입력에 `<label>`/`legend`, 결과 `aria-live`
- [ ] 사용법 안내(JPY 100엔 안내 포함)와 면책 문구(은행·시점·현찰/송금 차이) 존재
- [ ] "블로그로 돌아가기" 동작
