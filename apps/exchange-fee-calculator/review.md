## 요약

**판정: 수정 후 통과**

계산은 spec 예시 A~H 전 열과 무작위 20,000건 독립 BigInt 구현 비교에서 모두 0원 차이로 일치했다. 화면 동작·접근성·테마·아이콘도 통과했다. 구현자 보고 중 "통화 버튼이 좁은 화면에서 2×2로 줄바꿈"은 **사실이 아니었다**(300~360px에서 3+1로 깨짐). `style.css`를 고쳐 2×2가 되게 했다. 그 밖의 문제는 없었다.

## 구현자가 보고한 spec과 다른 점 평가

| 항목 | 평가 |
|---|---|
| 반환값에 `effRateText` 추가 | 수용. spec 8단계 표시 규칙(`1750 → 0.175%`, `0 → 0%`)을 BigInt로 정확히 만든다. |
| `formatRate`, `FX_CURRENCIES` 추가 export | 수용. 다만 `formatRate`는 내부에서 쓰이지 않는다(`calculate`가 `formatFixed`를 직접 호출). 해는 없다. |
| 통화·방향 오류 field(`currency`/`direction`) | 수용. 화면에서는 나올 수 없고, 잘못된 API 호출을 막는 방어 코드다. |
| 우대율 칸에 소수점 입력 허용 | 수용. spec 5장 "우대율 소수 → 정수로 입력" 안내를 보여 주려면 필요하다. 확인 결과 `90.5` → 안내 + `aria-invalid`. |
| 금액 힌트의 한글 단위는 1만 이상에서만 | 수용. `5,000위안 · 5,000 위안`처럼 같은 숫자가 반복되는 것을 피한다. |
| 매매기준율 힌트는 끝의 0을 지움 | 수용. spec 예시 "100엔당 900원"과 일치한다. |
| 긴 결과 금액은 줄 전체가 다음 줄로 | 수용. 320/375px 최대값에서 숫자가 중간에 끊기지 않고 카드 밖으로 넘치지 않음을 확인했다. |
| 통화 버튼이 좁은 화면에서 2×2 | **사실과 다름 → 수정함** (아래) |

## 발견한 문제와 수정 내역

### 1. 통화 세그먼트가 좁은 화면에서 2×2가 아니라 3+1로 줄바꿈 (수정함)

- **증상**: `flex-wrap` + `flex: 1 1 4.75rem` 구조라 300~360px 폭에서 USD·JPY·EUR이 한 줄, CNY 혼자 다음 줄에 꽉 차게 늘어났다. spec 8장은 "4칸 또는 2×2"를 요구한다.
- **수정** (`style.css`): `.fx-segment-currency`를 `display: grid; grid-template-columns: repeat(4, minmax(0, 1fr))`로 바꾸고, `@media (max-width: 374px)`에서는 `repeat(2, minmax(0, 1fr))`로 바꿨다. 라벨의 `flex: 1 1 4.75rem`는 지웠다.
- **재확인**: 1280/600/375px에서는 4칸 한 줄, 374/360/320/300px에서는 2×2. 라벨 넘침과 가로 스크롤은 없다. 전체 브라우저 테스트도 다시 돌려 통과했다.

## 남은 개선 제안 (선택)

- `formatRate`가 export만 되고 내부에서는 쓰이지 않는다. `calculate` 안의 적용 환율 문자열 생성에 쓰거나 export에서 빼면 더 깔끔하다.
- 우대율 0%일 때 결과 아래 안내("최대 ○원을 아낄 수 있어요")는 아주 큰 금액이면 320px에서 2~3줄이 된다. 동작에는 문제가 없다.
