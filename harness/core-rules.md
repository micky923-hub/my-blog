# 1층 공통 규칙 (모든 블루엠 프로젝트)

## 회사 원칙
* 상호는 "블루엠파트너스 / BlueM Partners". "주식회사"·"Co., Ltd."는 쓰지 않는다.
* 과장하지 않는다. "최고", "업계 1위", "100% 보장" 같은 말은 쓰지 않는다.
* 확인하지 못한 사실·숫자는 단정하지 않고 "(확인 필요)"라고 적는다.
* 고객사·파트너사 이름, 실적 숫자는 동의받은 것만 외부에 쓴다.

## 보안
* 비밀번호·API 키·토큰을 파일에 쓰지 않는다. 필요하면 GitHub Secrets나 배포 서비스의 환경 변수에만 둔다.
* `.env`, `*.db`, `*.pem`, `*.key` 같은 파일은 커밋하지 않는다. `.gitignore`로 막는다.
* 공개 저장소에는 회사 내부 자료(가격 원가, 계약 조건, 내부 메모)를 넣지 않는다.

## 개인정보
* 주민등록번호, 계좌번호, 신분증·사업자등록증 이미지, 개인 연락처 원본은 저장소에 넣지 않는다.
* 고객이 보낸 원본 자료는 `_workspace/`에 잠시 두고, 화면에 쓸 부분만 골라 정식 폴더로 옮긴다.
* 문의 양식 등으로 개인정보를 받으면 개인정보처리방침 페이지가 있어야 한다.

## 커밋·배포
* 작업은 브랜치에서 하고, 대표가 확인한 뒤 "머지해줘"로 `main`에 반영한다.
* 커밋 메시지는 한국어로 짧게: `영역: 무엇을 바꿨나` (예: `about: 회사 연혁 추가`).
* 배포 전 관문(GitHub Actions)이 초록불일 때만 배포한다. 빨간불이면 고친 뒤 다시 확인한다.
* 자동 배포 워크플로가 있으면 **배포 단계 바로 앞에 `bash harness/checks/gate.sh`를 넣는다.** 검사 워크플로가 따로 돌기만 하면 빨간불이어도 배포가 진행된다.
* AI는 초안까지만 만든다. 실제 배포·게시·결제·외부 서비스 가입은 사람이 한다 (프로젝트 `CLAUDE.md`에서 따로 허락한 경우 제외).

## 팀으로 일하기
* 블루엠의 여러 세션은 본부의 **팀 보드**를 함께 쓴다: 팀원 목록, 공유 할 일(대기 → 진행 → 완료), 팀원별 메일함.
* 작업을 시작할 때 내 할 일과 메시지를 확인하고, 시작·완료할 때 할 일 상태를 고친다. 앞선 일이 끝나지 않은 일은 시작하지 않는다.
* 다른 세션에 부탁할 일이 생기면 그 팀원의 메일함에 메시지를 남긴다. 급하면 세션 간 직접 메시지나 대표를 통해 전하고, 기록은 메일함에도 남긴다.
* 본부 저장소에 쓸 수 없는 세션은 보드에 적을 내용을 대표에게 주고 대신 적게 한다. 팀 보드 위치는 프로젝트 `CLAUDE.md`나 대표에게 확인한다.

## 자동 강제 (사람이 개입하지 않는 검문소)
규칙을 "읽고 지키는 것"에 기대지 않고, 정해진 순간에 검사가 **자동으로** 돈다.

| 검문소 | 언제 | 하는 일 |
|---|---|---|
| 프리커밋 훅 `harness/hooks/pre-commit` | 커밋 직전 (사람·AI 모두) | 린터가 형식(줄 끝 공백, 끝 줄 바꿈)을 자동 교정하고, 깨진 JSON·충돌 표시·비밀 정보는 커밋을 막는다 |
| Claude Code 훅 (`.claude/settings.json`) | AI가 명령을 실행하기 전 | `--no-verify`, 훅 끄기, 설치본 지우기를 막는다 |
| Claude Code 훅 | AI가 일을 끝내려 할 때 | 바뀐 것이 있으면 관문을 돌린다. 실패하면 끝내지 못하고 실패 내용을 받아 고친다 (자동 교정 루프). 3번 연속 실패하면 멈추고 대표에게 알린다 |
| GitHub Actions 관문 | 올린 뒤·배포 전 | 같은 관문. 실패하면 배포하지 않는다 |

* 훅이 막으면 검사를 끄거나 건너뛰지 않고 원인을 고친다. 검사가 틀렸다고 생각되면 아래 "하네스 피드백"으로 알린다.
* 프리커밋 훅은 설치할 때와 Claude 세션이 시작될 때 자동으로 켜진다 (`git config core.hooksPath harness/hooks`). 사람이 PC에서 처음 받았다면 이 명령을 한 번 실행한다.
* 프로젝트가 자기 훅 폴더를 따로 쓰거나 일부 Claude 훅을 빼야 하면(대표 승인 후) `harness.config.json`에 `"hooks": {"path": ".githooks", "skip": ["session-start"]}`처럼 적는다. 다시 설치해도 그대로 지켜진다. `skip`에 쓸 수 있는 것: `session-start`, `guard`, `stop`
* 끝내기 전 관문이 너무 오래 걸리는 프로젝트는 `harness.config.json`에 `"stopGate": false`로 끌 수 있다 (대표 승인 후).

## 청소 (가비지 컬렉션)
* 문지기(관문·훅)는 새로 들어오는 것만 본다. 시간이 지나 낡은 것은 **매달 청소**로 찾는다: `node harness/checks/sweep.mjs` (문서에 적힌 없는 파일·명령, 저장소 전체 관문, 안 쓰는 사진, 머지된 브랜치, TODO).
* 청소 검사는 아무것도 지우지 않고 후보 목록만 낸다. 지우는 것은 청소 PR로 올리고 대표 승인 뒤 반영한다 (`bluem-sweep` 순서).
* 늘 건너뛸 경로는 `harness.config.json`의 `"sweep": { "ignore": [...] }`에 적는다. 작업 기록(파일 이름에 spec·review·instructions·changelog가 든 문서, 바꾸려면 `"records"`)은 "없는 파일" 검사에서 뺀다.

## 개발팀 (AI 직원)
* 하네스가 프로젝트에 개발팀 AI 직원 셋을 설치한다: 개발자 `bluem-builder`(구현), 검토자 `bluem-reviewer`(따로 검토), 운영 담당 `bluem-devops`(배포 준비·장애·비용).
* **착수 관문**: 새 기능은 요구정의서(R-) → 기능정의서(F-) → 프로그램 설계서(일감 D-)를 대표가 승인한 뒤 시작한다. PR 제목·본문에 D-·F-번호를 적는다. 작은 일(문구·사진·버그 하나)은 `작은 수정`이라고 적고 바로 고친다. 양식은 본부 `templates/dev-docs/`
* 관문 검사로 켜기: `harness.config.json`에 `"devDocs": {"enabled": true, "design": ["저장소 안 설계서 경로"]}`. `design`이 비면(설계서가 본부에만 있음) PR 번호만 본다. 기존 프로젝트는 기본 꺼짐, 새 프로젝트 양식은 켜짐
* 기능을 만들 때는 개발자가 구현하고 관문을 통과시킨 뒤, **검토자가 따로** 본다. 만든 직원이 자기 변경을 검토하지 않는다.
* 직원 지침은 설치본이라 여기서 고치지 않는다. 그 프로젝트만의 일은 프로젝트 `CLAUDE.md`에 적는다.

## 루프 기록
* 훅이 결과를 `.git/bluem-loop.log`에 한 줄씩 남긴다 (작업 통과·막힘·멈춤, 커밋 교정·막힘, 명령 막힘). 커밋하지 않는 이 사본만의 기록이다.
* 일주일에 한 번, 또는 본부가 물으면 `bash harness/checks/loop-stats.sh`를 돌려 그 출력을 본부 메일함에 "루프 보고: {프로젝트}"로 보낸다. 같은 이유로 자주 막히면 아래 "하네스 피드백"도 함께 보낸다.

## 하네스 피드백
* 하네스를 쓰다가 겪은 일은 그냥 넘기지 않고 본부에 알린다: 검사가 잘못 막음, 막아야 할 것을 못 막음, 규칙이 헷갈림, 있었으면 하는 검사·절차.
* 알리는 법: 본부 메일함(팀 보드)에 제목 "하네스 피드백: {한 줄}" 메시지. 무엇을 하다가, 어떤 검사·규칙이, 어떻게 됐는지, 로그 한두 줄. 본부 저장소에 쓸 수 없는 세션은 같은 내용을 대표에게 준다.
* 기다리는 동안 설치본(`harness/`)을 직접 고치거나 검사를 끄지 않는다. 급하면 대표에게 묻는다.
* 그 프로젝트만의 사정이면 하네스 대신 프로젝트 `CLAUDE.md`(3층)에 적는다.

## 기본 검사
* 커밋 전에 `bash harness/checks/gate.sh`를 돌린다. 빌드(설정에 있으면)·기본 검사·유형별 검사를 한 번에 한다. 같은 검사가 GitHub Actions에서도 돈다.
* 관문이 지켜볼 브랜치는 `harness.config.json`의 `branches`에 적는다 (예: 작업 브랜치에서 바로 배포하는 프로젝트).
* 검사가 막은 내용이 정말 괜찮은 것이면, 검사를 끄지 말고 대표에게 묻는다.
