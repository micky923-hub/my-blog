# 1층 공통 규칙 (모든 블루엠 프로젝트)

## 회사 원칙
* 상호는 "블루엠파트너스 / BlueM Partners". "주식회사"·"Co., Ltd."는 쓰지 않는다.
* 과장하지 않는다. "최고", "업계 1위", "100% 보장" 같은 말은 쓰지 않는다.
* 확인하지 못한 사실·숫자는 단정하지 않고 "(확인 필요)"라고 적는다.
* 고객사·파트너사 이름, 실적 숫자는 동의받은 것만 외부에 쓴다.

## 보안
* 비밀번호·API 키·토큰을 파일에 쓰지 않는다. 필요하면 GitHub Secrets나 배포 서비스의 환경 변수에만 둔다.
* `.env`, `*.db`, `*.pem`, `*.key` 같은 파일은 커밋하지 않는다. `.gitignore`로 막는다.
* 공개 저장소에는 회사 내부 자료(가격 원가, 계약 조건, 내부 메모)를 넣지 않는다.

## 개인정보
* 주민등록번호, 계좌번호, 신분증·사업자등록증 이미지, 개인 연락처 원본은 저장소에 넣지 않는다.
* 고객이 보낸 원본 자료는 `_workspace/`에 잠시 두고, 화면에 쓸 부분만 골라 정식 폴더로 옮긴다.
* 문의 양식 등으로 개인정보를 받으면 개인정보처리방침 페이지가 있어야 한다.

## 커밋·배포
* 작업은 브랜치에서 하고, 대표가 확인한 뒤 "머지해줘"로 `main`에 반영한다.
* 커밋 메시지는 한국어로 짧게: `영역: 무엇을 바꿨나` (예: `about: 회사 연혁 추가`).
* 배포 전 관문(GitHub Actions)이 초록불일 때만 배포한다. 빨간불이면 고친 뒤 다시 확인한다.
* 자동 배포 워크플로가 있으면 **배포 단계 바로 앞에 `bash harness/checks/gate.sh`를 넣는다.** 검사 워크플로가 따로 돌기만 하면 빨간불이어도 배포가 진행된다.
* AI는 초안까지만 만든다. 실제 배포·게시·결제·외부 서비스 가입은 사람이 한다 (프로젝트 `CLAUDE.md`에서 따로 허락한 경우 제외).

## 기본 검사
* 커밋 전에 `bash harness/checks/gate.sh`를 돌린다. 빌드(설정에 있으면)·기본 검사·유형별 검사를 한 번에 한다. 같은 검사가 GitHub Actions에서도 돈다.
* 관문이 지켜볼 브랜치는 `harness.config.json`의 `branches`에 적는다 (예: 작업 브랜치에서 바로 배포하는 프로젝트).
* 검사가 막은 내용이 정말 괜찮은 것이면, 검사를 끄지 말고 대표에게 묻는다.
